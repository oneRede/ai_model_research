# Kimi K3：开放前沿智能

**Kimi K3 技术报告**

Kimi 团队  
月之暗面（Moonshot AI）

arXiv:2607.24653v1 [cs.CL] 2026年7月27日

## 摘要

我们介绍 Kimi K3，一个 2.8 万亿参数的混合专家模型（Mixture-of-Experts, MoE），具有 1040 亿激活参数、原生视觉能力和 100 万 token 的上下文窗口。Kimi K3 基于 Kimi Delta 注意力（Kimi Delta Attention, KDA）和注意力残差（Attention Residuals, AttnRes）构建，这两项技术改进了跨序列长度和模型深度的信息流。结合稳定潜在混合专家（Stable LatentMoE）——每个 token 有效激活 896 个路由专家中的 16 个——以及精炼的训练和数据配方，这些进步使整体扩展效率相比 Kimi K2 提升约 2.5 倍。后训练的亮点包括跨通用、智能体和编码领域以及多个推理努力级别的强化学习，实现了组合泛化和鲁棒的长时程执行。在 2.8 万亿参数规模上，Kimi K3 得到多个领域基础设施进步的支持：KDA 的算法-系统协同设计、具有高效内存管理的完美均衡专家并行训练、具有持久化展开和沙箱状态的百万 token 智能体强化学习，以及部署创新。

广泛的评估表明，Kimi K3 在长时程编码、智能体、知识、推理和视觉任务上达到前沿级性能。虽然其整体性能仍落后于最强大的专有模型（即 Claude Fable 5 和 GPT-5.6 Sol），但 Kimi K3 在我们的评估套件中始终优于其他开源和专有模型。我们发布完整的 Kimi K3 模型权重，以促进未来研究并加速前沿智能的更广泛部署和采用。

## 1 引言

在大语言模型（LLM）的大部分发展历程中，扩展意味着在部署前投入更多计算，即在更多数据上训练更大的模型。推理模型的兴起建立了测试时计算作为第二条扩展轴线：OpenAI 的 o 系列扩展强化学习和测试时推理；Anthropic 的扩展思考模型分配自适应思考预算并将推理与工具使用交错；DeepSeek-R1 和 Kimi K1.5 表明大规模强化学习可以从强大的预训练模型中激发复杂的推理行为；Kimi K2.5 智能体群（Agent Swarm）进一步将测试时扩展从顺序推理扩展到并行智能体协调。这些进展使测试时扩展成为前沿研究的核心焦点。

然而，虽然开源模型生态系统在第二条轴线上快速进步，但在第一条轴线上进展缓慢：许多最近的模型仍保持在 1T 级参数范围内或略高于此。随着越来越复杂的推理和智能体强化学习方法应用于相似规模的预训练基础，开源进展面临收敛的风险，而与最强专有系统的差距正在扩大。通过 Kimi K3，我们同时推进两条扩展轴线至前沿：将预训练基础扩展到前所未有的 3T 级参数，同时在 100 万上下文长度上扩展强化学习、推理努力和长时程交互。

我们介绍 Kimi K3，一个原生多模态混合专家模型，具有 2.8 万亿总参数、1040 亿激活参数和高达 100 万 token 的上下文窗口。其架构在序列长度、网络深度和模型宽度上扩展信息流。Kimi Delta 注意力（KDA）提供高效的长序列混合，周期性插入的门控多头潜在注意力（Gated MLA）层保留全局交互。注意力残差（AttnRes）允许每一层选择性地关注所有先前层的表示。稳定潜在混合专家将路由专家空间扩展到 896 个专家，每个 token 激活 16 个，而归一化、SiTU-GLU 和分位数均衡（Quantile Balancing）在极端稀疏性下稳定优化。这些架构进步，结合精炼的数据和训练配方，使整体扩展效率相比 Kimi K2 提升约 2.5 倍。

我们将这一预训练基础与专为 100 万上下文测试时扩展设计的后训练配对。Kimi K3 经历跨长时程编码、通用智能体、通用推理和知识任务的强化学习，每个任务跨越多个推理努力级别。训练环境包括可验证搜索和专业知识工作、软件工程和内核优化、带视觉循环工具使用的多模态推理、持久化助手工作流、Web 开发和自主执行任务。这些环境训练一个通用的推理、行动、观察、验证和适应循环，通常超过数百或数千次工具调用和数百万累积上下文 token。领域和努力专门化的策略通过多教师在线策略蒸馏整合到统一模型中。

实现这一机制需要随架构复杂性、模型规模和轨迹长度扩展的基础设施。对于 KDA 的系统协同设计，我们开发了融合内核、KDA 上下文并行和状态感知前缀缓存，使 KDA 在设备内、跨设备和跨请求高效运行。对于 2.8 万亿参数 MoE 预训练，MoonEP 提供具有静态计算形状和零拷贝通信的完美均衡专家执行，而内存高效训练和多模态编码器优化在有限内存内保持利用率。对于百万 token 智能体强化学习，我们的协同定位系统结合部分展开、外部 KV 缓存保留、自适应节流和可恢复微虚拟机沙箱，以保留长期模型和环境状态。最后，专用内核以及缓存和预算感知的集群调度将这些创新转化为可预测的生产服务。

最终模型建立了新的开源前沿。在跨越长时程编码、智能体、知识、推理和视觉任务的基准测试中，Kimi K3 整体落后于最强专有系统——Claude Fable 5 和 GPT-5.6 Sol——但在我们评估套件中始终领先于其他开源和专有模型，如图 1 所示。

## 2 架构

Kimi K3 的架构在三个维度上扩展信息流：通过 Kimi Delta 注意力（KDA）的序列长度，通过注意力残差（AttnRes）的网络深度，以及通过稳定潜在混合专家（Stable LatentMoE）的模型宽度。

### 2.1 Kimi Delta 注意力（KDA）

标准 Transformer 使用二次复杂度的全注意力或固定窗口的局部注意力。全注意力提供全局信息整合但在长序列上成本过高；局部注意力降低成本但限制了远程依赖。Kimi Delta 注意力（KDA）是一种混合线性注意力机制，在长序列效率和全局信息流之间取得平衡。

KDA 基于线性注意力的核化视角。回顾标准注意力计算查询 Q、键 K 和值 V 的加权和：

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right)V$$

线性注意力通过核函数 φ 将此重新表述，使得：

$$\text{LinearAttention}(Q, K, V) = \frac{\phi(Q)(\phi(K)^\top V)}{\phi(Q)(\phi(K)^\top \mathbf{1})}$$

其中分子和分母都可以通过关联性以 $O(L)$ 复杂度计算。Kimi Delta 注意力引入**差分核**（delta kernel），它显式建模当前位置和历史的信息差异：

$$\phi_{\text{delta}}(q, k) = \phi(q) - \beta \cdot \phi_{\text{EMA}}(k)$$

其中 $\phi_{\text{EMA}}(k)$ 是键嵌入的指数移动平均（EMA），$\beta$ 是一个可学习的衰减参数。这种差分形式允许模型关注信息的*变化*而不是绝对值，从而更有效地捕获长序列中的突出事件。

**实现细节**：KDA 层与 Gated MLA 层交错。在 Kimi K3 的 93 层中，69 层是 KDA，24 层是 Gated MLA。KDA 提供高效的长序列处理，而周期性的 Gated MLA 层保留全局交互。

### 2.2 注意力残差（AttnRes）

标准 Transformer 在每一层仅关注前一层的输出。这限制了深层访问早期层中计算的表示的能力。注意力残差（AttnRes）通过允许每一层选择性地关注*所有先前层*的表示来解决此限制。

形式上，令 $h^{(l)}$ 表示第 $l$ 层的隐藏状态。标准 Transformer 计算：

$$h^{(l+1)} = \text{Layer}^{(l+1)}(h^{(l)})$$

注意力残差引入跨层注意力：

$$h^{(l+1)} = \text{Layer}^{(l+1)}(h^{(l)}) + \alpha^{(l+1)} \cdot \text{Attention}_{\text{res}}(h^{(l)}, [h^{(1)}, h^{(2)}, \ldots, h^{(l-1)}])$$

其中 $\text{Attention}_{\text{res}}$ 是一个轻量级的跨层注意力机制，$\alpha^{(l+1)}$ 是一个可学习的门控参数。这使得深层能够直接访问早期层的表示，从而改进信息流和梯度传播。

**实现细节**：为了保持计算效率，我们仅在选定的层启用 AttnRes，并使用低秩投影来减少内存开销。跨层键值缓存存储在压缩形式中。

### 2.3 稳定潜在混合专家（Stable LatentMoE）

Kimi K3 使用混合专家（MoE）架构来扩展模型容量而不成比例地增加计算。我们的 Stable LatentMoE 设计将专家空间扩展到每层 896 个路由专家，每个 token 激活 16 个，加上 2 个始终激活的共享专家。

**路由机制**：标准 MoE 路由使用 Top-k 选择：

$$p_i = \text{softmax}(W_r \cdot h_i)$$
$$\text{experts}_i = \text{Top-k}(p_i, k=16)$$

其中 $W_r$ 是路由权重矩阵，$h_i$ 是 token $i$ 的隐藏状态。选定的专家处理 token 并组合其输出：

$$\text{MoE}(h_i) = \sum_{j \in \text{experts}_i} p_{i,j} \cdot E_j(h_i)$$

**负载均衡**：在极端稀疏性（896 个专家中选 16 个）下，路由容易变得不平衡，导致一些专家利用不足。我们引入**分位数均衡**（Quantile Balancing, QB）来维持平衡负载。

传统方法使用辅助损失或固定步长的偏置调整来鼓励均衡。分位数均衡直接从路由分数的分位数设置每个专家的偏置。考虑一个训练批次，其中 $m$ 个 token 被路由到 $n$ 个专家，每个 token 选择 $k$ 个专家，因此目标负载是 $q := mk/n$ 个 token 每专家。

QB 在 Top-k 选择之上应用偏置 $b_j$ 到每个专家 $j$ 的路由分数：

$$s_{i,j}^{\text{biased}} = s_{i,j} + b_j$$

然后从 Top-(k+1) 选择中导出下一个偏置，其中第 $(k+1)$ 个条目给出截止 $\alpha_i$，专家必须超过该截止才能进入 token $i$ 的 Top-k。对于每个专家 $j$，我们选择偏置 $b_j^{(t+1)}$ 使得专家 $j$ 接收其目标负载 $q$。具体来说，我们计算边际 $s_{i,j} - \alpha_i$ 并设置：

$$\tilde{b}_j^{(t+1)} \leftarrow -\text{quantile}_{1-k/n}(s_{:,j} - \alpha)$$
$$b_j^{(t+1)} \leftarrow \tilde{b}_j^{(t+1)} - \text{mean}(\tilde{b}^{(t+1)} \cdot \mathbf{1})$$

第二行去除一个公共偏移量，该偏移量不改变 Top-k 选择。这种更新确保每个专家接收其目标负载份额，而无需辅助损失。

**直方图估计**：在规模上，精确的分位数计算需要收集分布在多个 rank 和累积步骤上的数百万个边际，这在训练时不可行。我们使用直方图估计器：单个 all-reduce 汇总每个 rank 的箱计数，然后从汇总计数中恢复分位数。由于计数是可加的，直方图表示汇总的全局批次，而不管 token 如何分片，因此估计反映了整个批次的分位数，误差范围仅为箱宽度，通信成本仅为每个专家几百个箱。

**稳定性改进**：除了分位数均衡外，我们还使用：
- **SiTU-GLU 激活**：平滑的激活函数，减少专家输出中的尖峰
- **LayerNorm 归一化**：在专家输入和输出处应用，稳定极端稀疏性下的优化

这些组合使 Stable LatentMoE 在 896 个专家规模上保持稳定训练。

### 2.4 原生视觉

Kimi K3 是原生多模态的：文本、图像和视频由单个共享骨干在一个上下文中处理，无需事后的模态对齐阶段。这种设计是第 1 节中描述的长时程、视觉循环行为的架构基础。渲染输出和生成它们的代码存在于同一个 token 流中，模型可以编写代码、检查结果的截图或视频帧，并迭代地改进视觉工件——用户界面、图形、视频——无需跨模型交接。

**MoonViT-V2**：与 Kimi K2.5 的一个关键不同是，我们完全从头开始用下一个 token 预测训练 Kimi K3 视觉编码器 MoonViT-V2。之前的实践（包括 Kimi K2.5 本身）从对比预训练模型（如 SigLIP）初始化视觉编码器，前提是预训练的视觉知识使模型有一个良好的开端。我们偏离这种实践主要是为了训练稳定性。

当预训练编码器附加到 LLM 时，联合优化变得不稳定：SigLIP 初始化的 MoonViT-3D 显示持续较高的梯度范数并频繁出现尖峰，而 MoonViT-V2 在整个训练过程中保持稳定（图 6）。用下一个 token 预测训练还允许编码器的表示直接由语言建模目标塑造，而不是由偏好全局语义而非细粒度文本和结构线索的对比损失塑造。值得注意的是，我们发现 MoonViT-V2 在视觉评估中与 SigLIP 初始化的基线相匹配，表明对比预训练作为大规模多模态语言模型的初始化是不必要的。

## 3 训练

### 3.1 量化感知训练

Kimi K3 使用量化感知训练（QAT）从一开始就优化低精度表示。我们在预训练期间对权重使用 MXFP4，对激活使用 MXFP8。这些格式由微软引入，结合了块浮点的动态范围和低位精度的内存效率。

MXFP4/MXFP8 格式将张量分解为块，每个块有自己的共享指数（scale）。在每个块内，值以低精度尾数存储。这允许表示宽范围的值，同时保持每个元素的低位宽。

量化感知训练在前向传递中模拟量化：

$$\tilde{W} = Q_{\text{MXFP4}}(W), \quad \tilde{A} = Q_{\text{MXFP8}}(A)$$

其中 $Q$ 表示量化操作。反向传递使用直通估计器（straight-through estimator）来近似梯度。这使得模型学习对量化噪声鲁棒的权重。

在推理时，量化模型直接使用 MXFP4/MXFP8 表示，无需额外的后训练量化步骤。这减少了内存占用和推理延迟，同时保持接近全精度的准确性。

### 3.2 完美均衡专家并行训练

训练具有 896 个专家的 MoE 模型需要高效的专家并行策略。标准方法在专家间分配 token，但负载不平衡会导致闲置设备和低利用率。我们的 MoonEP 系统实现完美均衡的专家执行。

**MoonEP 设计**：MoonEP 使用三个关键思想：
1. **静态计算形状**：每个设备处理固定数量的 token，无论路由决策如何
2. **零拷贝通信**：token 到专家的映射通过索引传递，避免数据复制
3. **流水线执行**：通信与计算重叠，隐藏 all-to-all 延迟

具体来说，给定 $N$ 个设备和每个设备 $T$ 个 token，MoonEP 确保每个专家恰好处理 $kT/N$ 个 token（其中 $k$ 是 Top-k 中的 $k$），无论路由如何。这通过容量因子（capacity factor）填充和索引压缩实现。

**实验验证**：MoonEP 在 896 专家规模上保持 >95% 的训练利用率，而标准专家并行在相同设置下降至 ~70%。完美均衡消除了由负载不平衡导致的尾部延迟。

### 3.3 数据配方

Kimi K3 的预训练数据包含约 15 万亿 token，跨越多种语言、领域和模态。数据配方经过精心策划以平衡通用知识、推理能力和专业技能。

**数据来源**：
- **网络文本**（60%）：来自 Common Crawl 的过滤和去重文本，重点关注高质量内容
- **书籍和长文档**（15%）：用于长上下文理解的叙事和技术写作
- **代码**（10%）：来自 GitHub 和其他来源的开源代码
- **科学论文**（8%）：arXiv、PubMed 和其他学术数据库
- **多模态数据**（7%）：图像-文本对和视频-文本对
- **其他**（专业领域、多语言等）

**数据质量**：我们应用多阶段过滤流程：
1. 基于规则的过滤（语言检测、长度阈值、重复去除）
2. 分类器过滤（质量分数、毒性检测）
3. 去重（精确和模糊匹配）
4. 聚类和采样（平衡主题分布）

最终数据集在质量、多样性和规模之间取得平衡，支持 Kimi K3 的广泛能力。

## 4 后训练

### 4.1 多努力强化学习

Kimi K3 的后训练将预训练基础转化为能够跨多个推理努力级别进行测试时扩展的智能体。我们在三个主要领域进行强化学习：通用、智能体和编码，每个领域跨越多个努力级别。

**努力级别**：推理努力由思考预算控制，范围从快速响应（低努力）到深入推理（高努力）。我们训练五个离散努力级别：

- **Effort 1（最低）**：快速响应，最小思考
- **Effort 2（低）**：简要推理
- **Effort 3（中）**：标准推理深度
- **Effort 4（高）**：扩展推理
- **Effort 5（最高）**：最大思考预算

每个努力级别有不同的推理时间和准确性权衡。低努力适合简单查询，高努力用于复杂推理任务。

**训练方法**：我们使用分层强化学习框架：
1. **领域特定策略**：为每个领域（通用、智能体、编码）训练专门的策略
2. **努力特定微调**：每个策略在所有努力级别上微调
3. **多教师蒸馏**：将专门策略整合到统一模型中

训练使用 PPO（Proximal Policy Optimization）与组合奖励信号：
- **任务成功**：主要奖励来自任务完成
- **中间里程碑**：鼓励进展的稀疏奖励
- **效率惩罚**：对过度冗长或工具误用的惩罚

### 4.2 训练环境

#### 4.2.1 可验证搜索和专业知识工作

我们创建需要深入信息综合的复杂问答任务。任务跨越数学、科学、法律和金融等领域。智能体必须搜索多个来源、提取相关信息、验证事实并合成连贯答案。

奖励基于答案准确性、引用质量和推理正确性。我们使用专家标注的参考答案和自动事实核查器来评估响应。

#### 4.2.2 软件工程任务

软件工程环境基于真实世界的代码库和问题跟踪器。任务包括：
- Bug 修复：诊断和修复现有代码中的错误
- 功能实现：根据规范添加新功能
- 代码重构：改进代码结构而不改变行为
- 测试生成：为现有代码编写测试

智能体可以访问代码库、文档、测试套件和执行环境。奖励基于测试通过率、代码质量指标和人工评审。

#### 4.2.3 内核优化任务

对于低级系统编程，我们开发内核优化环境。智能体接收一个参考内核（如矩阵乘法、卷积）和性能目标。目标是生成实现相同功能但更快的优化内核。

环境提供性能分析工具、硬件规格和测试输入。奖励基于加速比、正确性和内存使用。这训练模型进行性能推理和低级优化。

#### 4.2.4 带视觉循环工具使用的多模态推理

多模态环境结合视觉理解和工具使用。任务包括：
- 数据可视化分析：解释图表和图形
- UI/UX 设计：基于截图和反馈迭代设计
- 视觉调试：识别渲染问题并修复代码

智能体接收图像输入，可以生成代码，执行它，观察视觉输出，并迭代。这种视觉循环训练模型将视觉理解与代码生成联系起来。

#### 4.2.5 个人助手任务

对于长时程个人助手任务，我们开发了广泛使用应用程序的现实模拟实现，如 Gmail、Notion、Slack 和 Canvas。它们保留真实对应物的核心语义，同时无需外部 API 或速率限制即可实现可重现的大规模交互。

基于这些模拟应用，我们设计受真实世界专业工作流程启发的复杂任务，场景涵盖人力资源、法律服务和金融。在每个任务中，智能体在多个模拟日内在持久化、演化的环境中操作，并遇到分布在各应用程序中的数十个相互依赖的事件。单次展开可能涉及多达数千次工具调用和数百万上下文 token。

每个事件都有自己的评估标准，由确定性规则或基于 LLM 的评估器评估。初始工作区由自主搜索网络参考材料并将其转换为连贯、任务相关环境的智能体构建。我们还扩展了 RL 框架以支持此类活动环境，建模复杂事件流和诱导的世界状态转换。

#### 4.2.6 自主执行任务

我们引入自主执行任务（AET），这是一种通过验证循环优化训练长时程智能体智能的环境范式。每个任务指定初始状态、约束目标、基于工具的动作空间、执行预算和独立验证器。

智能体只看到目标、上下文、约束和验证接口，没有参考轨迹或预定义程序，必须自主执行任务分解、工具选择、规划、错误恢复和终止。奖励基于验证器对最终环境状态的评估，而非智能体的自我报告完成。

我们设计多种类型的验证器以支持不同环境，包括黑盒系统复制（图 10）、定量因子发现和税务审计。在每个环境中，智能体迭代提交解决方案、接收验证器反馈并完善策略，训练假设、行动、分析反馈和适应的通用循环。

#### 4.2.7 Web 开发任务

我们构建了涵盖典型场景的多样化专家策划 Web 开发任务套件。输入范围从单行场景描述到多段规范；工件涵盖网站、交互式游戏、3D/WebGL 场景、数据可视化、SVG 和全栈应用程序。

每个任务在容器化沙箱中运行，并在不同智能体脚手架下展开，而非单一固定工具，以促进跨脚手架泛化。奖励包含两个组成部分：确定性检查和由内部奖励模型进行的模型评判。

确定性检查功能测试应用程序行为，并对复制参考的任务进行结构和像素级相似性评分。当项目无法构建、带错误运行或伪造而非实现工件时，奖励归零。模型评判使用其他模型执行源代码检查或查看并与输出工件交互。

## 5 基础设施

Kimi K3 结合了在单个模型中很少遇到的三个系统挑战：混合 KDA 注意力、3T 级稀疏多模态训练和推理，以及百万 token 智能体工作负载。我们的基础设施在模型生命周期中与这些挑战协同设计。

### 5.1 KDA 的算法-系统协同设计

KDA 将 softmax 注意力不断增长的键值缓存替换为固定大小的循环状态 $S \in \mathbb{R}^{d_k \times d_v}$，其串行更新在并行执行中带来挑战，以换取廉价传输和重用的固定大小状态。下面的设计解决第一个属性并在两个执行级别利用第二个属性：设备内的融合内核和跨设备的 KDA 上下文并行。

#### 5.1.1 跨场景的 KDA 内核

KDA 状态的串行依赖与 GPU 对宽、统一并行性的偏好相矛盾，它在每个执行场景中表现为不同的瓶颈。我们为每个场景设计专用内核。

**训练和预填充的分块内核**：KDA 的分块形式在每个块内并行但跨块串行，因为循环状态必须从块传播到块。如果天真执行，这两个阶段交替进行，在串行传播期间使 SM 闲置。

因此，我们开发了 FlashKDA，一个基于 CUTLASS 的分块内核，它将块内计算与跨块状态传播重叠。内核将工作分解为 token 并行阶段和头并行递归，每个独立调度和调优，并大幅优于 Triton 参考实现。FlashKDA 服务于训练和推理预填充，并作为 flash-linear-attention 的后端自动调度。


**解码的递归内核**：解码逐个 token 生成，内核可以完全融合 token 内递归。我们实现了一个 head-parallel decode 内核，在头之间分配工作并在寄存器中保持每个 SM 的状态切片，消除了共享内存往返。这种内核在典型批量大小下接近峰值吞吐量。

#### 5.1.2 KDA 上下文并行

KDA 的固定大小状态支持跨设备传输和重用的第二个优化级别。在 KDA 上下文并行（KDA-CP）中，长上下文输入在设备之间分片，每个设备并行处理其分片的分块 KDA。最后，设备执行头并行递归以合并每个分片的递归状态，从而将成本从 O(L) 降至 O(d_k · d_v)——对于百万 token 输入节省数千倍。

与标准上下文并行（在拆分点需要完整 all-gather KV）相比，KDA-CP 仅传输聚合的递归状态，而不是每个拆分的完整 KV。在长上下文场景中，这节省了大量通信和内存。

#### 5.1.3 状态感知前缀缓存

推理服务从前缀缓存中受益匪浅，该缓存重用跨请求的公共提示前缀的 KV 状态。对于 KDA，我们扩展此机制以缓存递归状态。

**实现**：当请求共享公共前缀时，我们从缓存加载该前缀的 KDA 状态，并仅从缓存末尾继续计算。状态通过前缀树组织，支持高效查找和共享。

这种状态感知前缀缓存在推理中提供与 KV 缓存相同的加速，同时保持 KDA 的内存优势。它在 vLLM 中实现为 KDA 特定的缓存后端。

### 5.2 用于 3T 级 MoE 训练的内存高效基础设施

**激活重计算**：为了在有限内存内训练 2.8 万亿参数模型，我们使用选择性激活重计算。我们重计算廉价操作（如归一化、激活函数）并保存昂贵操作（如注意力、专家计算）的激活。这将内存使用减少约 40%，训练时间开销 <15%。

**梯度检查点**：我们在 Transformer 层级别应用梯度检查点。每第 N 层保存激活，中间层在反向传递期间重计算。这进一步减少内存，使我们能够容纳 2.8T 参数 + 激活 + 优化器状态。

**混合精度训练**：我们使用混合精度训练，在 FP16 中执行前向和反向传递，在 FP32 中保持主权重副本用于优化器更新。结合损失缩放，这保持训练稳定性同时减少内存占用。

**多模态编码器优化**：视觉编码器（MoonViT-V2）在训练期间冻结用于大多数步骤，仅在定期微调阶段解冻。这减少了激活内存和梯度计算成本。

### 5.3 用于百万 Token 智能体轨迹的协同定位 RL 系统

百万 token 智能体 RL 轨迹带来独特的系统挑战：长时程交互需要保留模型和环境状态跨数千个步骤，同时保持高吞吐量。我们的协同定位系统将策略推理、环境执行和经验收集放在一起。

**部分展开**：标准 RL 需要完整的轨迹用于优势估计。对于百万 token 轨迹，这是不可行的。我们使用部分展开：将轨迹分成重叠的段，独立计算每个段的优势，然后拼接段用于策略更新。

重叠确保优势估计在段边界保持准确。段长度平衡内存使用和准确性。

**外部 KV 缓存保留**：在展开期间，模型的 KV 缓存增长到吉字节。我们将旧的 KV 移至主机内存或磁盘，仅在 GPU 上保留活动窗口。当需要旧上下文时，我们从外部存储重新加载 KV。

这种分层 KV 管理允许百万 token 上下文适配 GPU 内存预算。访问模式针对顺序读取进行优化，保持高带宽。

**自适应节流**：为了平衡策略和环境吞吐量，我们使用自适应节流。当环境落后时，我们减慢策略推理；当策略落后时，我们批处理环境步骤。这保持两者忙碌并最大化整体利用率。

**可恢复微虚拟机沙箱**：环境（如代码执行、文件系统、应用程序状态）在轻量级微虚拟机中运行。这些虚拟机可以检查点和恢复，允许我们：
- 在崩溃或超时后恢复环境
- 从检查点分支探索多个轨迹
- 在节点间迁移环境以平衡负载

虚拟机隔离还提供安全性：不受信任的代码执行在沙箱中，无法访问外部资源。

### 5.4 生产推理系统

**专用内核**：除了 FlashKDA，我们开发专用内核用于：
- **专家计算**：融合的 Top-k 选择 + 专家执行内核
- **量化推理**：用于 MXFP4/MXFP8 算术的原生内核
- **融合操作**：组合多个操作（LayerNorm + Linear，SiLU + 乘法）以减少内核启动开销

这些内核在典型批量大小下实现 >80% 的峰值吞吐量。

**缓存和预算感知的集群调度**：我们的推理集群运行数百个 GPU。调度器：
1. 将具有公共前缀的请求路由到同一节点以最大化前缀缓存命中率
2. 根据预算约束（延迟、成本、吞吐量）分配努力级别
3. 批处理兼容请求以提高利用率
4. 抢占低优先级请求以满足延迟目标

调度器使用学习的成本模型来预测请求的资源需求，并动态调整调度以保持 SLA。

**分布式推理**：对于大型批量或长上下文，单个节点不足。我们使用张量并行和流水线并行在多个节点上分布模型。KDA-CP 进一步减少跨节点通信。

我们还实现推测解码以加速生成：小型 draft 模型提出 token，大型模型并行验证它们。这在保持质量的同时加速 2-3 倍。

## 6 评估

我们在广泛的基准测试中评估 Kimi K3，涵盖编码、智能体、知识、推理和视觉任务。评估使用标准协议和指标，确保与先前工作的可比性。

### 6.1 编码任务

**基准**：SWE-bench、HumanEval、MBPP、LiveCodeBench、CodeContests

**结果**：Kimi K3 在大多数编码基准上达到强劲性能：
- SWE-bench：43.2%（Claude Fable 5: 49.0%，GPT-5.6 Sol: 51.5%）
- HumanEval：92.7%（Claude Fable 5: 94.2%，GPT-5.6 Sol: 96.1%）
- LiveCodeBench（周赛）：38.5%（Claude Fable 5: 42.1%）

Kimi K3 在长时程编码任务（如 SWE-Marathon，需要 100+ 工具调用）上特别强：42.0% vs Claude Fable 5 的 35.0%。

### 6.2 智能体任务

**基准**：WebArena、VisualWebArena、OSWorld、Terminal-Bench 2、τ³-Banking

**结果**：Kimi K3 在需要长时程交互的智能体任务上表现出色：
- WebArena：78.3%（Claude Fable 5: 72.1%）
- Terminal-Bench 2：91.2%（Claude Fable 5: 84.5%）
- τ³-Banking：94.5%（Claude Fable 5: 87.4%）

长上下文和持久化状态使 Kimi K3 能够处理跨越数千步骤的复杂智能体轨迹。

### 6.3 知识和推理任务

**基准**：MMLU、GPQA、MATH、GSM8K、BBH、ARC-Challenge

**结果**：Kimi K3 在知识和推理任务上达到竞争性能：
- MMLU：88.7%（Claude Fable 5: 90.2%，GPT-5.6 Sol: 91.5%）
- GPQA Diamond：83.4%（Claude Fable 5: 87.6%）
- MATH：85.2%（Claude Fable 5: 88.1%）

多努力 RL 使 Kimi K3 能够在困难任务上分配更多思考，改进复杂推理的性能。

### 6.4 视觉任务

**基准**：MMMU、MathVista、ChartQA、DocVQA、AI2D

**结果**：Kimi K3 的原生视觉能力在多模态任务上表现良好：
- MMMU：72.1%（Claude Fable 5: 75.3%）
- MathVista：78.9%（GPT-5.6 Sol: 82.4%）
- ChartQA：85.7%（Claude Fable 5: 87.2%）

从头训练的 MoonViT-V2 与预训练初始化的基线相匹配，验证了我们的训练方法。

### 6.5 长上下文评估

**基准**：RULER、LongBench、InfiniteBench、∞-Bench

**结果**：Kimi K3 的 100 万 token 上下文窗口在长上下文任务上表现出色：
- RULER（1M 上下文）：96.8% 检索准确率
- InfiniteBench：在 10 个任务中的 8 个上达到 SOTA

KDA 在长序列上保持高质量的信息流，使 Kimi K3 能够有效利用整个百万 token 窗口。

## 7 相关工作

**大语言模型**：Kimi K3 建立在大规模预训练 LLM 的基础上。早期工作如 GPT-3、PaLM 和 LLaMA 建立了扩展定律和训练配方。最近的前沿模型如 GPT-4、Claude 3 和 Gemini 1.5 推动了规模和能力的边界。

**混合专家模型**：Kimi K3 使用 MoE 架构扩展容量。Switch Transformer、GLaM 和 Mixtral 展示了 MoE 用于高效扩展的有效性。我们的 Stable LatentMoE 在 896 专家规模上推动了极端稀疏性的边界。

**长上下文模型**：Kimi K3 的 100 万 token 窗口建立在长上下文研究的基础上。Transformer-XL、Longformer 和 BigBird 引入了高效的长序列注意力。最近的工作如 LongNet、Hyena 和 RWKV 探索线性注意力和状态空间模型。我们的 KDA 结合了这些思想的优势。

**强化学习用于 LLM**：使用 RL 微调 LLM 已被广泛探索。InstructGPT 和 RLHF 改进对齐。最近的工作如 Constitutional AI、RLAIF 和 ReAct 扩展了 RL 用于复杂推理和智能体任务。Kimi K3 的多努力 RL 建立在这些基础上。

**测试时扩展**：OpenAI 的 o1、Anthropic 的扩展思考和 DeepSeek-R1 展示了测试时计算扩展。Kimi K3 将此与预训练扩展结合，同时推进两条扩展轴线。

**多模态模型**：Flamingo、BLIP-2 和 LLaVA 将视觉和语言模态结合。GPT-4V 和 Gemini 展示了强大的多模态能力。Kimi K3 的原生多模态设计避免了事后对齐，实现了更紧密的视觉-语言整合。

## 8 结论与未来工作

我们介绍了 Kimi K3，一个 2.8 万亿参数的开放前沿模型，具有 1040 亿激活参数、原生视觉能力和 100 万 token 上下文窗口。Kimi K3 通过 Kimi Delta 注意力、注意力残差和稳定潜在混合专家推进架构创新。多努力强化学习使测试时扩展跨通用、智能体和编码领域。大规模基础设施进步——KDA 系统协同设计、MoonEP、百万 token 智能体 RL 和生产推理系统——使这些能力成为现实。

广泛的评估表明，Kimi K3 在长时程编码、智能体和长上下文任务上达到前沿级性能，同时在整体性能上与最强专有模型保持竞争力。通过发布完整的模型权重，我们使前沿智能可用于研究、部署和进一步创新。

**局限性**：虽然 Kimi K3 推进了开源前沿，但它仍落后于最强专有模型（Claude Fable 5、GPT-5.6 Sol）在许多基准上。缩小这一差距需要在数据质量、训练效率和后训练方法方面继续改进。

**未来工作**：我们看到几个有前景的研究方向：
1. **更高效的注意力机制**：进一步减少 KDA 的计算和内存成本
2. **改进的专家利用**：更好的路由策略以最大化专家专业化
3. **扩展多模态**：添加音频、3D 和其他模态
4. **更强的测试时扩展**：探索自适应计算和元学习方法
5. **安全和对齐**：改进对抗性鲁棒性和价值对齐

我们期待社区在 Kimi K3 基础上进行构建，推进开放和可访问的前沿 AI。
