# KIMI K3：开放前沿智能

**KIMI K3 技术报告**

Kimi 团队

arXiv:2607.24653v1 [cs.CL] 2026年7月27日

## 摘要

我们推出 Kimi K3，这是一个拥有 2.8 万亿参数的混合专家模型。该模型具有 1040 亿激活参数量、原生视觉能力以及 100 万 token 的上下文窗口。

Kimi K3 基于 Kimi Delta Attention [63] 和 Attention Residuals [57] 构建，这两项技术改善了信息在序列长度和模型深度上的流动。结合 Stable LatentMoE（每个 token 有效激活 896 个路由专家中的 16 个）以及精炼的训练和数据方案，这些进展使得整体扩展效率相比 Kimi K2 [58] 提升了约 2.5 倍。

后训练的亮点在于跨通用、智能体和编码领域以及多个推理努力级别的强化学习。这实现了组合泛化和稳健的长时程执行。在 2.8 万亿规模上，Kimi K3 得益于多个领域的基础设施进步：针对 KDA 的算法-系统协同设计、具备高效内存管理的完美平衡专家并行训练、具有持久化展开和沙盒状态的百万 token 智能体强化学习，以及部署创新。

广泛的评估表明，Kimi K3 在长时程编码、智能体、知识、推理和视觉任务上达到了前沿级别的性能。尽管其整体性能仍落后于最强大的闭源模型——即 Claude Fable 5 和 GPT-5.6 Sol，但 Kimi K3 在我们的测试套件中始终优于其他开源和闭源模型。我们发布完整的 Kimi K3 模型权重，以促进未来研究并加速前沿智能的更广泛部署和应用。

## 1 引言

在大语言模型（LLM）发展的大部分时期，扩展意味着在部署前投入更多计算资源，通过在更多数据上训练更大的模型来实现 [54, 45]。推理模型的兴起确立了测试时计算作为第二个扩展维度。

OpenAI 的 o 系列扩展了强化学习和测试时推理 [84, 83]。Anthropic 的扩展思考模型分配自适应思考预算并将推理与工具使用交织 [6, 7]。DeepSeek-R1 [40] 和 Kimi K1.5 [118] 表明大规模强化学习可以从强大的预训练模型中激发出复杂的推理行为。而 Kimi K2.5 Agent Swarm [59] 进一步将测试时扩展从顺序推理延伸到并行智能体协调。

这些进展使测试时扩展成为前沿研究的核心焦点。然而，尽管开源模型生态系统在第二个维度上快速推进，但在第一个维度上进展缓慢。许多近期模型仍停留在或略高于 1 万亿级参数范围 [145, 29, 135, 120]。随着越来越复杂的推理和智能体强化学习方法应用于规模相似的预训练基础，开源进展面临收敛风险，而与最强闭源系统的差距则不断扩大。

通过 Kimi K3，我们在两个扩展维度上同时推进到前沿：将预训练基础扩展到前所未有的 3 万亿级参数，同时在 100 万上下文长度上扩展强化学习、推理努力和长时程交互。

我们推出 Kimi K3，这是一个原生多模态混合专家模型，拥有 2.8 万亿总参数、1040 亿激活参数量，以及最多 100 万 token 的上下文窗口。其架构在序列长度、网络深度和模型宽度上扩展信息流动。

Kimi Delta Attention（KDA）[63] 提供高效的长序列混合，并周期性地插入 Gated MLA 层以保持全局交互。Attention Residuals（AttnRes）[57] 允许每一层选择性地关注来自所有先前层的表示。Stable LatentMoE 将路由专家空间扩展到 896 个专家，每个 token 激活 16 个，而归一化、SiTU-GLU 和 Quantile Balancing 在极端稀疏性下稳定优化。

这些架构进步与精炼的数据和训练方案相结合，使得整体扩展效率相比 Kimi K2 [58] 提升了约 2.5 倍。

我们将这个预训练基础与专为 100 万上下文测试时扩展设计的后训练相结合。Kimi K3 经历了跨长时程编码、通用智能体、通用推理和知识任务的强化学习，每项任务跨越多个推理努力级别。

训练环境包括可验证搜索和专业知识工作、软件工程和内核优化、具有视觉循环工具使用的多模态推理、持久化助手工作流、Web 开发和自主执行任务。这些环境训练了一个包含推理、行动、观察、验证和适应的通用循环，通常涉及数百或数千次工具调用以及累积数百万上下文 token。

领域和努力专门化的策略通过多教师在线蒸馏 [75, 134, 29] 整合到统一模型中。

实现这一机制需要能够随架构复杂性、模型规模和轨迹长度扩展的基础设施。对于 KDA 的系统协同设计，我们开发了融合内核、KDA 上下文并行和状态感知前缀缓存，使 KDA 在设备内、跨设备和跨请求中都能高效运行。

对于 2.8 万亿参数混合专家模型预训练，MoonEP 提供了具有静态计算形状和零拷贝通信的完美平衡专家执行，而内存高效训练和多模态编码器优化在有限内存内维持利用率。对于百万 token 智能体强化学习，我们的协同定位系统结合了部分展开、外部 KV 缓存保留、自适应节流和可恢复的微虚拟机沙盒，以保持长期存活的模型和环境状态。

最后，专用内核以及缓存和预算感知的集群调度将这些创新转化为可预测的生产服务。

最终模型建立了新的开放前沿。在跨越长时程编码、智能体、知识、推理和视觉任务的基准测试中，Kimi K3 总体上落后于最强大的闭源系统——Claude Fable 5 和 GPT-5.6 Sol——但在我们的测试套件中始终领先于其他开源和闭源模型，如图 1 所示。

我们的贡献总结如下：

- **开放前沿的预训练**：我们训练了一个 2.8 万亿参数的原生多模态混合专家模型，具有 1040 亿激活参数量和 100 万 token 的上下文窗口。KDA、AttnRes、Stable LatentMoE、精炼的数据和训练方案共同使整体扩展效率相比 Kimi K2 提升了约 2.5 倍。

- **多努力测试时扩展的强化学习**：我们跨通用、智能体和编码领域以及多个推理努力级别进行强化学习，然后将生成的能力整合到统一模型中。

- **多万亿参数、百万 token 智能的基础设施**：我们引入了 KDA 系统协同设计；用于 2.8 万亿参数混合专家模型预训练的 MoonEP 和内存高效基础设施；具有可恢复沙盒的协同定位强化学习系统，用于百万 token 智能体轨迹；以及更多基础设施创新。

- **一个开放前沿模型**：我们发布完整的 Kimi K3 模型权重，使前沿智能可用于研究、部署和进一步创新。

## 2 模型架构

Kimi K3 架构旨在沿三个互补维度扩展信息流动：序列长度、网络深度和模型宽度。

在序列维度上，混合注意力将三个 Kimi Delta Attention（KDA）[63] 层与每个块中的一个 Gated MLA 层结合，为长上下文 token 混合提供高效机制，同时保留选择性的高容量注意力（§2.1）。

在深度维度上，Attention Residuals（AttnRes）[57] 使每个模块能够选择性地从嵌入、当前块和先前块中检索表示，将信息访问扩展到传统顺序残差累积之外（§2.2）。

在宽度维度上，每个注意力层后跟一个 Stable LatentMoE 层，执行稀疏通道混合，每个 token 有效激活 896 个路由专家中的 16 个（§2.3）。

对于原生视觉，MoonViT-V2 编码图像和视频，轻量级投影器在主干处理前将生成的视觉特征映射到共享嵌入空间（§2.4）。

结合 Per-Head Muon（§2.5），这些组件提供了一个统一的架构，用于跨 token、层和通道扩展信息流动。与精炼的训练和数据方案相结合，它们使整体扩展效率相比 Kimi K2 提升了约 2.5 倍。图 2 提供了架构概览。

**图 2**：Kimi K3 架构，围绕 token、通道和层混合组织，输入端具有原生视觉路径。每个块包含三个 Kimi Delta Attention（KDA）层和一个 Gated MLA 层，每个注意力层与一个 Stable LatentMoE 前馈网络配对。Attention Residuals（AttnRes）使用学习的伪查询（w）来计算嵌入和先前块输出的注意力权重（α），实现跨深度的选择性信息流动。左上：Stable LatentMoE 模块，包含共享专家和路由专家。左下：KDA 模块。右下：原生视觉路径。

### 2.1 混合注意力

Kimi K3 使用线性注意力和全局注意力的逐层混合，将 KDA [63] 与 Gated MLA 结合。每个块包含 3 个 KDA 层和 1 个 Gated MLA 层，混合比例为 3:1。这种模式在整个主干中重复。两种注意力机制分别描述如下。在主干末端放置一个额外的 Gated MLA 层，确保最后一层始终执行全局注意力。

#### 2.1.1 Kimi Delta Attention

KDA 通过通道级遗忘门扩展了 delta 规则递归 [105, 138] [63]。考虑一个隐藏状态序列 xt ∈ Rd，其中 t 索引 token 位置，d 是模型隐藏维度。为清晰起见，我们首先描述单个注意力头，具有查询和键向量 qt、kt ∈ Rdk，值向量 vt ∈ Rdv，以及递归状态 St ∈ Rdk×dv。

KDA 在 delta 规则更新前应用通道级衰减：

St = [I − βt kt kt⊤] Diag(αt)St−1 + βt kt vt⊤,    õt = S⊤t qt.

这里，αt ∈ (0, 1)dk 是通道级单步保留因子，βt ∈ (0, 1) 控制 delta 规则写入强度。遵循 Kimi Linear [63]，KDA 将每头量参数化为：

qth, kth = L2 Norm[Swish(ShortConv(Wq/k h xt))] ∈ Rdk,
vth = Swish(ShortConv(Wvh xt)) ∈ Rdv,
βth = Sigmoid(Wβh xt) ∈ (0, 1),
zth = Wα↑ Wα↓ xt + bhα ∈ Rdk.

查询、键和值投影应用 ShortConv 后跟 Swish [138]，查询和键进一步使用 L2 Norm 归一化 [141]。低秩投影和头特定偏置 bhα ∈ Rdk 为每个键通道生成细粒度衰减 logit zth。从 zth 到 αht 的下界映射在下面的分块形式后介绍。

**分块并行形式**

遵循 Kimi Linear [63]，KDA 在块间递归，在每个块内并行。对于块大小 C，X[t] 堆叠第 t 个块中 X ∈ {Q, K, V, O, U, W} 的 token 向量。矩阵 S[t] ∈ Rdk×dv 表示进入块 t 的递归状态。对于位置 1 ≤ i ≤ j ≤ C，定义通道级累积衰减：

γ[t]i→j := ∏(r=i to j) αr[t],    γ[t]r := γ[t]1→r.

如 Kimi Linear 中，Γ[t] ∈ RC×dk 按行堆叠 γ[t]1, ..., γ[t]C。UT 变换产生 U[t] 和 W[t]，从中我们定义伪值项 Ṽe[t] := U[t] − W[t] S[t]。给定传入状态 S[t]，块 t 中的所有输出并行计算为：

A[t] = Tril[(Q[t] ⊙ Γ1→C[t])(K[t] /Γ1→C[t])⊤],
O[t] = (Γ1→C[t] ⊙ Q[t])S[t] + A[t] Ṽe[t].
       |_____块间_____| |__块内__|

对于矩阵 M，Tril(M) 将所有严格上三角元素设为零并保留下三角元素，包括对角线。这个掩码在块内强制因果交互，保留对角线是因为每个输出读取当前 token 更新后的状态。O[t] 中的第一项携带来自先前块的信息，而第二项考虑当前块内的交互。我们建议读者参阅 Kimi Linear [63] 了解 UT 变换和分块形式的完整推导。

**下界衰减**

公式 4 通过倒数累积衰减 1/Γ1→C[t] 重新缩放每个块中的键。因为 Γ1→C[t] 是 (0, 1) 中保留因子的乘积，这个倒数可能无界增长并在有限精度下溢出 [140, 63]。

Kimi Linear 通过在对数空间计算相对衰减并将每个块划分为次级 16-token 块来控制这个数值范围 [140, 63]。非对角块可以直接在 Tensor Core 上使用密集矩阵乘法计算。相比之下，对角块仍需要显式的位置对计算，这仍是块内的主要瓶颈。

Kimi K3 通过改变从衰减 logit zth 到每步对数衰减 gth 的映射来解决这个瓶颈。遵循 GDN 和 Mamba-2，Kimi Linear 使用负 Softplus 映射 gth = −eAh Softplus(zth) ∈ (−∞, 0)dk [138, 24, 63]。Kimi K3 改用缩放的 sigmoid 从下方限制对数衰减：

gth = gmin Sigmoid(eAh zth) ∈ (gmin, 0)dk,
αht = exp(gth) ∈ (egmin, 1)dk,

其中 Ah 是可学习的每头对数尺度，gmin = −5 固定。我们初始化 Ah = 0，每个偏置 bhα 按 [63, 24, 138] 初始化。

当 gmin = −5 时，每个保留因子满足 αt,jh > e−5 ≈ 6.7 × 10−3，16-token 块上的累积对数衰减位于 (−80, 0)。相应的倒数重缩放因子因此小于 e80 并保持在 BF16 动态范围内。这个有限范围允许对角和非对角块都使用密集 Tensor Core 矩阵乘法，消除了位置对对角路径。

这种参数化与先前工作中的下界递归门密切相关 [97, 27, 91]。图 3 说明了衰减参数化的变化及其计算后果。

**图 3**：下界衰减及其对分块 KDA 计算的影响。(a) Kimi Linear 使用无界负 Softplus 映射，而 Kimi K3 用缩放的 sigmoid 限制对数衰减；曲线显示 A = 0 和 gmin = −5。(b) Kimi Linear 用显式位置对计算评估每个对角块，而 Kimi K3 中的有界范围允许所有因果块使用密集 Tensor Core 矩阵乘法。

**全秩门**

最后，Kimi K3 将 KDA 的输出门从 Kimi Linear [63] 使用的低秩参数化改为输入依赖的全秩投影。在对递归输出应用头级 RMSNorm [146] 后，KDA 应用数据依赖的输出门控 [99]：

yt = Wo [Sigmoid(Wg xt) ⊙ RMSNorm(õt)].

#### 2.1.2 Gated MLA

DeepSeek-V2 引入的多头潜在注意力（MLA）[29] 通过低秩投影压缩键值缓存。Kimi K3 遵循 Kimi K2 的 Gated MLA 变体，该变体在注意力输出上应用数据依赖的门控。详细信息可以在 Kimi K2 技术报告 [58] 中找到。

### 2.2 Attention Residuals

Attention Residuals（AttnRes）[57] 使每一层能够选择性地从所有先前层检索表示，而不是仅从前一层检索。每个块计算对嵌入和所有先前块输出的注意力权重，使用学习的伪查询向量。这些权重调制来自不同深度的信息流，使模型能够根据需要跳过或组合层。

AttnRes 的实现细节遵循 Kimi K2.5 [59]，其中伪查询通过轻量级 MLP 从当前块的输入派生。

### 2.3 Stable LatentMoE

Kimi K3 采用 Stable LatentMoE 进行稀疏前馈计算，每层有 896 个路由专家，每个 token 激活 16 个，外加 2 个共享专家始终激活。这种极端稀疏性（激活率 < 2%）需要特别注意训练稳定性和负载平衡。

#### 2.3.1 LatentMoE

LatentMoE [29] 通过低秩投影压缩专家输入和输出，减少通信开销。对于输入 x，路由器选择 Top-k 专家集合 T(x)，每个专家 j ∈ T(x) 接收压缩输入 xc = Wdown x 并产生压缩输出 yj,c，最终输出为：

y = Wup ∑(j∈T(x)) pj yj,c,

其中 pj 是归一化的路由权重。压缩维度通常是隐藏维度的 0.5 倍，大幅减少专家间通信。

#### 2.3.2 SiTU-GLU

标准 MoE 使用 SwiGLU [106] 作为专家内激活函数。在极端稀疏性下，我们观察到 SwiGLU 的无界输出可能导致训练不稳定。Kimi K3 引入 SiTU-GLU（Sigmoid-Tanh Unit GLU），用软上界替换 Swish 激活：

SiTU(x; β) = x · β tanh(x/β),
SiTU-GLU(x) = SiTU(Wgate x; β1) ⊙ SiTU(Wup x; β2).

针对 Kimi K3，我们设置软上限超参数为 β1 = 4（门控分支）和 β2 = 25（上行分支）。缩放的 tanh 在原点附近近似线性，在大幅度时有界，使得 SiTU-GLU 能够保留 SwiGLU 的局部响应，同时控制乘积中的两个因子。

图 4 对比了 GLU、SwiGLU 和 SiTU-GLU 在同一切片上的分支定义和标量响应。§ B 给出了局部展开、极限情况、形式化输出边界以及与硬截断的比较。

#### 2.3.3 分位数平衡

与基于辅助损失的路由不同 [33]，Kimi K3 采用无辅助损失路由 [30]。负载平衡通过在用于 Top-k 选择的路由得分中添加专家特定偏置 bj 来实现。对于 token xi，路由器计算 si = Sigmoid(Wr xi) 并应用：

Ti = argtopk(si + b),    pi,j = si,j / ∑(r∈Ti) si,r,    j ∈ Ti.

由于 b 在 pi,j 中被省略，它调节分发而不改变混合权重或路由器的基于梯度的优化。

原始方法使用固定步长规则 bj(t+1) = bj(t) + γ sign(ℓ̄ − ℓj(t)) 更新 b [30]，其中 γ 在缓慢适应和负载振荡之间权衡。随着 LatentMoE 将每层的路由专家池增加到 896 个，维持平衡负载变得更具挑战性。不平衡路由会减慢专家并行训练，并可能导致某些专家训练不足 [47]。

为解决这一限制，我们引入**分位数平衡（QB）**，它根据与目标负载匹配的路由得分分位数来设置每个专家偏置 [111]。

考虑一个包含 m 个 token 的训练批次，通过 Top-k 选择路由到 n 个专家，因此目标负载为 q := mk/n 个 token 每专家。QB 从单次前向传播中推导下一个偏置。路由将 Top-k 选择替换为对偏置得分 si + b(t) 的 Top-(k+1)：前 k 个条目是实际采用的路由，而第 (k+1) 个条目是截止值 αi(t)，专家必须超过该值才能进入 token i 的 Top-k。

从 Top-(k+1) 路由中获取截止值避免了单独的 token 侧分位数。然后我们选择每个专家偏置，使专家 j 接收其目标负载：在截止值固定的情况下，在候选偏置 b̂j(t+1) 下路由到专家 j 的 token 计数为：

∑(i=1 to m) 1[si,j + b̂j(t+1) > αi(t)],

它在阈值 −b̂j(t+1) 中单调递减。假设没有平局，将此计数设置为 q 使得 −b̂j(t+1) 成为第 (q+1) 大的边距 si,j − αi(t)，因此恰好 q 个边距保持在阈值之上。

由于 q/m = k/n，这是跨 token 边距的 (1 − k/n) 分位数，给出 QB 更新：

b̂j(t+1) ← − quantile(1−k/n)[s:,j − α(t)],
b(t+1) ← b̂(t+1) − mean(b̂(t+1)) · 1.

边距从原始得分 si,j 中减去偏置截止值 αi(t)，因此旧偏置仅通过截止值进入更新，第二行移除一个不改变 Top-k 选择的公共偏移量。为了因果性，更新仅在下一步生效 [30]，即批次永远不会使用从自身派生的偏置进行路由。

图 5 展示了 m = 8、n = 4 和 k = 1 的情况，其中每个专家接收目标负载 q = 2。最终偏置在推理时冻结。平衡分配推导在 § C 中给出。

**直方图估计**

在大规模情况下，公式 14 中的分位数跨越完整的全局批次，其边距数以百万计并分布在各个 rank 和累积步骤中，因此在训练时收集它们以计算精确分位数是不可行的。

### 2.4 原生视觉

Kimi K3 原生支持多模态：文本、图像和视频在单一上下文中由单一共享骨干网络处理，无需事后模态对齐阶段。这种设计是 §1 中描述的长时程、视觉在环行为的架构基础。

渲染输出和产生它们的代码位于同一 token 流中，模型可以编写代码、检查结果的截图或视频帧，并迭代改进视觉产物——用户界面、图形、视频——无需跨模型交接。

与 Kimi K2.5 的一个关键区别是，我们完全从零开始使用下一个 token 预测训练 Kimi K3 视觉编码器 MoonViT-V2。包括 Kimi K2.5 本身在内的先前实践，从对比预训练模型（如 SigLIP）初始化视觉编码器，前提是预训练的视觉知识为模型提供先机。

我们放弃这种实践主要是为了训练稳定性。当预训练编码器附加到 LLM 时，联合优化变得不稳定：SigLIP 初始化的 MoonViT-3D 持续显示更高的梯度范数并伴有频繁尖峰，而 MoonViT-V2 在整个训练过程中保持稳定（图 6）。

使用下一个 token 预测进行训练还允许编码器的表示直接由语言建模目标塑造，而不是由偏向全局语义而非细粒度文本和结构线索的对比损失塑造。值得注意的是，我们发现 MoonViT-V2 在各项视觉评估中与 SigLIP 初始化的基线相匹配，表明对比预训练作为大规模多模态语言模型的初始化是不必要的。

**图 6**：我们预训练消融实验中的视觉塔梯度范数。与 SigLIP 初始化的 MoonViT-3D 相比，从零开始的 MoonViT-V2 保持较低的梯度范数并减少尖峰，表明优化更稳定。

**架构**

该训练方案建立在遵循 Kimi K2.5 整体设计的视觉通路上 [59, 61]：视觉输入首先由 MoonViT-V2 编码，然后通过轻量级 MLP 投影器映射到 LLM。

MoonViT-V2 是一个 27 层视觉 Transformer，约有 0.4B 参数，采用 RMSNorm 并从其线性和注意力投影中移除所有偏置项，这种设计进一步稳定了上述从零开始的优化。

图像和视频使用完全共享的参数处理，如 MoonViT-3D：注意力分解为帧内空间和帧间时间传递，时间池化进一步沿时间维度压缩 token。在投影之前，通过 2 × 2 下采样的像素重排操作将视觉 token 数量减少四倍，使高达 3584 × 3584 像素的输入在 1M token 上下文中保持可负担。

### 2.5 逐头 Muon

继 Kimi K2 之后，Kimi K3 采用 Muon [53] 作为其矩阵参数的优化器。对于注意力投影，我们进一步将其细化为逐头变体：不是对完整的 Q、K 和 V 投影矩阵应用 Newton–Schulz 正交化，而是沿头维度分区其动量矩阵，并分别正交化每个头的块。

直觉是完整矩阵正交化将所有头视为单一耦合块，因此具有较大梯度或动量规模的头主导共享更新方向，而较小规模的头接收归一化不足的更新；逐头正交化使跨头更新规模均衡。

在实践中，这种设计在更大规模上产生更平衡的跨头学习动态并提高训练稳定性。它还略微减少优化器开销，因为对高瘦逐头块的 Newton–Schulz 迭代比对完整投影矩阵的迭代更便宜。

## 3 预训练

### 3.1 预训练数据

Kimi K3 在涵盖四个主要文本领域的精选语料库上进行预训练——网络文本、代码、数学和知识——以及大规模视觉语料库。视觉数据涵盖标题、交错的图像-文本文档、OCR、感知、视频和视觉编码数据。我们的数据管道建立在为 Kimi K2 [58] 开发并在 Kimi K2.5 [59] 中完善的管道基础上。

**文本数据**

每个领域通过基于规则的启发式、基于分类器的质量评分和去重的组合进行过滤。领域特定的采样率由小型模型的消融研究确定。

遵循 Kimi K2 的改写方案 [58]，我们使用风格和视角多样化提示、逐块自回归生成以及针对源文档的保真度验证来改写知识和数学语料库。

**视觉数据**

视觉语料库遵循 Kimi K2.5 的分类法 [59]，结合开源集合与内部过滤、合成和去重管道。训练期间，坐标监督以绝对和归一化（[0,1]）格式提供，实现精确且分辨率鲁棒的定位。

除了经典的文本标注图像外，我们大幅扩展程序化多模态数据，将代码片段与其跨特定领域格式（包括 SVG、3D 资产、网页、游戏和 CAD 示意图）的渲染视觉效果耦合。

### 3.2 缩放定律

总的来说，前面章节中描述的架构、数据和训练改进定义了我们的新模型家族。由于这些变化也改变了最优训练方案，我们进行专门的缩放定律研究以重新调整关键超参数，包括批量大小、学习率、每参数 token 比率（TPP）和模型形状。

在保留的 OOD 验证数据上评估，缩放定律曲线（图 7）显示这些改进共同在整体缩放效率上相对于 Kimi K2 实现了约 2.5 倍的提升。表 1 提供了 Kimi K2 和 Kimi K3 之间的详细架构对比，突出了促成这一改进的结构变化。

我们的缩放定律研究一致倾向于余弦衰减而非 Warmup Stable Decay（WSD）[46]，促使我们采用余弦衰减作为默认学习率调度。我们在固定最小学习率下比较余弦衰减和 WSD。

尽管先前工作报告 WSD 可以匹配甚至超越余弦衰减，但我们观察到这两种调度表现出明显不同的最优超参数。即使在相同的模型大小和训练 token 预算下，它们的最优峰值学习率和批量大小也大不相同。

因此，使用共享超参数集比较两种调度可能不公平地偏向其中一种，仅仅因为这些超参数与它更好对齐。为确保公平比较，我们为每种调度进行独立的缩放定律搜索。在各自的最优超参数设置下，余弦衰减持续实现比 WSD 更低的最终损失。

### 3.3 训练方案

Kimi K3 采用原生多模态训练策略，其中语言和视觉从训练开始就联合优化，而不是通过事后对齐阶段将视觉编码器嫁接到预训练语言模型上。

在此范式下，视觉和文本 token 在单一下一个 token 预测目标中交错，使共享骨干网络从一开始就学习统一的多模态表示。

我们使用逐头 Muon 优化器（§ 2.5）以及 Kimi K2 中引入的权重裁剪机制优化模型，同时采用 QB（§ 2.3.3）进行混合专家模型负载平衡。我们使用带 1% 线性预热的余弦学习率调度。权重衰减在整个过程中设置为 0.1。

我们的预训练从 8k token 的上下文长度开始，随后在后续训练阶段扩展到 64k token。

### 3.4 长上下文扩展

**位置编码**

Kimi K3 不使用显式位置嵌入（NoPE），而是通过 KDA 的循环门控和衰减机制隐式编码位置信息。因此，模型直接外推到 1M token 上下文，无需任何位置编码修改，如 RoPE 重缩放或插值 [92]。

**长上下文数据**

来自自然源的长文档和视频包含大量低质量内容，包括近似重复、二进制块、截断文件、视频片段和无效的机器生成日志。因此，我们通过专门的清洗管道处理它们。

该管道结合精确和模糊去重，补充视频帧上的感知哈希，以及基于启发式和分类器的质量过滤和结构验证。由于真正长而连贯的文档和视频相对于短文本稀缺，我们对它们进行上采样，以免在冷却阶段长上下文分布被短序列淹没。

然而，仅凭长度本身并不赋予长程能力。为解决这个问题，我们通过仔细排列和连接多模态文档和子任务来合成额外的长上下文数据。这使得嵌入的任务只能通过关注分散在完整 1M token 上下文中的信息来解决。这在预期规模上训练注意力机制并防止其退化为局部模式。

**渐进上下文扩展**

Kimi K3 支持高达 100 万 token 的上下文窗口。我们通过随着训练进行渐进扩展上下文窗口来实现这一点，遵循四阶段课程。

窗口在预训练期间从 8K 增长到 64K token，在冷却阶段从 256K 增长到 1M token。将昂贵的长序列计算集中在整体训练预算的一小部分内，使课程在经济上可行，同时仍允许模型逐渐适应越来越长程的依赖关系。

使百万 token 训练对 KDA 层可行的序列维度分区在 § 5.1.2 中描述。

## 4 后训练

### 4.1 方法

我们的后训练管道遵循三阶段范式：
1. 通过监督微调（SFT）初始化基线智能体能力
2. 通过强化学习（RL）在不同推理努力水平下开发专业领域专家
3. 使用多教师在策略蒸馏（MOPD）将这些领域特定策略整合到单一模型中

#### 4.1.1 监督微调

SFT 阶段为后续 RL 阶段建立高质量冷启动策略。在先前 Kimi 模型的 SFT 管道基础上 [58, 59]，我们扩展了 Kimi K3 的 SFT 数据集，大幅拓宽其对复杂智能体任务的覆盖。

具体而言，我们使用先前 Kimi 系列的领域专业模型合成数据轨迹，然后进行多阶段验证和人工在环标注。为一致表示这些复杂的智能体轨迹，我们使用基于 XTML 的聊天模板序列化所有数据（可扩展 Token 标记语言；详见 § F）。

总体而言，这些步骤产生了一个大规模指令数据集，赋予 Kimi K3 自适应推理、精确工具调用以及在长时程智能体场景中的鲁棒执行能力。此外，我们从 SFT 阶段开始应用量化感知训练（QAT），使用 MXFP4 权重和 MXFP8 激活（§ 4.1.4）。

#### 4.1.2 强化学习

虽然 SFT 提供了坚实的冷启动基础，但 RL 对于解锁高阶推理和执行能力至关重要。

我们不是为单个任务训练专门的 RL 模型，而是在三个广泛领域扩展 RL，每个领域涵盖广泛的子任务，并为每个推理努力水平的每个领域训练单一专家：

1. **通用任务**：涵盖通用体验、视觉、推理、忠实性、搜索能力和知识工作任务
2. **通用智能体**：涵盖长时程助手任务、深度研究和段落级写作
3. **编码智能体**：涵盖软件工程（SWE）、编码体验、内核任务和 Web 开发

如图 8 所示，扩展 RL FLOPs 持续改进知识、推理、视觉、通用智能体和编码等各种能力。将这三个领域专家与 {low, high, max} 中的三个推理努力水平交叉，总共产生九个专家模型。

**图 8**：RL 期间各种公开和内部评估的得分和平均助手步数。通过扩展 RL FLOPs，工具调用步数持续扩展，伴随着模型整体能力的全面提升。

**算法**

为缓解在长时程任务中加剧的长尾延迟，我们扩展了同步 RL 框架 [118, 59] 的部分滚动方案。

在每次迭代的滚动阶段，我们为 N 个提示中的每一个采样 K 个完成，维持 N × K 条轨迹的活跃工作负载。生成阶段不是等待所有滚动终止，而是在一部分 λ ∈ (0, 1) 的轨迹完成（即 λNK）时立即暂停，允许策略优化在没有执行落后者的情况下进行。

暂停的滚动被加入队列并优先在下一次迭代开始时恢复，由我们的沙箱基础设施驱动（§ 5.3.2）。一旦提示的所有 K 个响应完成，它们立即被分派进行策略优化，该优化遵循 Kimi K2.5 [59] 中的算法。

在我们的部分滚动方案下，单个长时程轨迹自然跨越多次迭代，引入威胁训练稳定性的数据陈旧性。我们的策略优化算法通过逐 token 正则化固有地容忍这种极端离策略机制。通过将策略更新约束在局部邻域内，这种正则化使算法能够鲁棒地处理高度陈旧的数据并维持训练稳定性。

**推理努力**

为在最大化 token 效率的同时微调推理努力，我们在 RL 期间实施逐问题预算控制机制 [59]。我们将每个问题 x 与从冷启动模型估计的初始 token 预算 b0(x) 关联，并对总 token 预算 T(y) 超过缩放阈值 τ · b0(x) 的轨迹用 −1 覆盖任务奖励。

对于通用任务，T(y) 测量思考 token 数，而对于智能体任务，T(y) 考虑累积输出 token，包括推理轨迹和工具调用参数。

训练遵循预算乘数 τ 上的阶段式课程。我们首先使用相对较大的 τ 训练最大预算变体，同时仍限制最大预算以抑制过度思考。然后我们将 τ 退火到较小值以获得高努力和低努力专家模型。τ 的调整在人工在环指导下按领域配置。

由所有推理水平的专家产生的轨迹被联合收集用于监督微调和多教师在策略蒸馏。

**智能体生成奖励模型**

对于不可验证的通用任务，我们采用智能体生成奖励模型（GRM），保留锦标赛风格的组奖励与二元比较，如 Kimi K2.5 [58, 59]。

除了用于增强判断的通用智能体能力外，智能体评判需要遵循强制协议：
1. 阅读结果、产品或文本输出
2. 生成评分标准
3. 根据评分标准为每个候选打分
4. 在记分板中记录评分标准分配的分数

为缓解奖励黑客行为导致输出越来越冗长，我们应用类似于上述推理努力控制的基于预算的冗长度控制：给定从冷启动模型估计的初始冗长度 ℓ0 和乘数 σ，输出长度超过 σ · ℓ0 的候选在二元比较中自动失败。

#### 4.1.3 多教师在策略蒸馏

我们采用多教师在策略蒸馏（MOPD）将这些跨不同推理努力的领域专业能力整合到统一模型中 [75, 134, 29]。

MOPD 允许单一学生模型从多个教师专家学习，每个教师专家针对特定领域和推理努力水平进行了优化。这种方法使最终模型能够在不同任务和努力级别之间灵活切换，同时保持紧凑的推理时开销。

具体实施细节遵循 Kimi K2.5 [59] 中描述的方法，其中学生模型通过同时匹配多个教师的输出分布来进行训练。

#### 4.1.4 量化感知训练

从 SFT 阶段开始，我们应用量化感知训练（QAT），使用 MXFP4 权重和 MXFP8 激活。这种方法在训练期间模拟量化效果，使模型能够学习对量化误差更鲁棒的表示。

QAT 使最终部署模型能够在保持高精度的同时显著减少内存占用和计算开销，这对于在资源受限环境中服务 2.8 万亿参数模型至关重要。

### 4.2 训练环境

我们的强化学习训练涵盖多个专门设计的环境，每个环境针对特定能力领域：

#### 4.2.1 软件工程任务

软件工程（SWE）环境模拟真实的代码库维护和开发任务。智能体必须理解现有代码、诊断问题、实施修复并验证其解决方案。这些任务通常涉及数千行代码的上下文和多次工具调用的迭代调试周期。

#### 4.2.2 Web 开发任务

Web 开发环境要求智能体编写和迭代改进 Web 应用程序。模型可以编写代码、查看渲染输出的截图或视频帧，并基于视觉反馈进行迭代改进。这直接利用了原生多模态架构，使代码和其视觉输出位于同一上下文流中。

#### 4.2.3 多模态推理任务

这些任务结合视觉输入与工具使用，要求智能体理解图像和视频内容，提取相关信息，并执行需要视觉和文本推理的复杂任务。

#### 4.2.4 内核优化任务

为了增强 Kimi K3 的 GPU 内核优化能力，我们构建了一个大规模内核任务集合。该任务集涵盖从单算子内核到融合大型内核的各类任务，这些任务来自 Flash Linear Attention [139] 等高质量 GitHub 仓库。

该任务集涵盖多种 GPU 编程方法，包括 CUDA、Triton、CuTe DSL、Gluon、ThunderKittens [110] 和 TileLang [129]，并覆盖广泛使用的 GPU 架构和数值格式，包括 BF16、FP8 和 FP4。

奖励机制同时评估正确性和性能：每个内核都提供 PyTorch 参考实现，超出预定义数值误差阈值的解决方案会获得零奖励。性能根据专家实现进行评分，匹配专家实现可获得 0.5 奖励，接近硬件理论峰值性能则可将奖励提升至 1。

为确保奖励反映真实优化成果，我们开发了一套黑客检测系统。该系统对 CUDA 图回放、输入缓存和精度降低等奖励作弊策略进行惩罚，并在 Kimi K3 的开发过程中持续扩展，加入针对新发现作弊策略的防护措施。

#### 4.2.5 个人助理任务

对于长时程个人助理任务，我们为 Gmail、Notion、Slack 和 Canvas 等广泛使用的应用开发了真实的模拟实现。这些模拟保留了真实应用的核心语义，同时实现了可重复的大规模交互，无需依赖外部 API 或受到速率限制。

基于这些模拟应用，我们设计了受真实世界专业工作流程启发的复杂任务，涵盖人力资源、法律服务和金融等场景。在每个任务中，智能体在一个持续演化的环境中运行，跨越多个模拟日，并遇到分布在各个应用中的数十个相互依赖的事件。

单次执行可能涉及多达数千次工具调用和数百万个上下文 token。每个事件都有自己的评估标准，通过确定性规则或基于大语言模型的评估器进行评估。

初始工作空间由智能体构建，它们自主搜索网络以获取参考资料，并将其转化为连贯且与任务相关的环境。我们还扩展了强化学习框架以支持这类动态环境，对复杂的事件流和由此引发的世界状态转换进行建模。

### 4.3 对话模板

Kimi K3 对话模板围绕三个目标重新设计：

1. **可扩展性**：新功能应该通过向后兼容的消息格式引入，而不是通过模板修订，以便单个模板服务于整个模型世代。

2. **低对齐税**：该格式应该可以用最少的监督数据学习，支持轻度微调的预训练模型可以直接进入强化学习的流程。

3. **解码友好性**：结构应该支持简单的编码器、流式解析器和语法约束强制器。

为此，模板采用 **XTML（可扩展 Token 标记语言）**，这是一种类似 XML 的标记。其中尖括号语法被三个保留的特殊 token 替换：[open]、[sep] 和 [close]，并附加 [end_of_msg] token 作为生成停止标记。

元素 [open]tag attr="value"[sep] ... [close]tag[sep] 与其 XML 对应物同构，但每个结构边界都是显式的特殊 token。这消除了元素边界处的分词歧义，并简化了受约束的解码。

**消息与区域**

上下文的顶级单元是消息，消息按来源分为两类（图 16a）。输入消息序列化请求的 messages 字段，涵盖熟悉的 system、user、assistant 和 tool 角色。

选项消息将请求选项转换为模型在上下文中读取的指令，它们的放置反映了它们的范围。全局选项——工具声明（type="tool-declare"）和推理努力设置——出现在所有输入消息之前：它们管理整个会话并很少更改，因此修改它们无论如何都会使 KV 缓存失效。

一次性选项（tool_choice、response_format）在输入消息之后附加，以便每次请求的更改使历史 KV 缓存保持完整。第三种类型，输入选项消息，与输入消息交错以在会话中期补充或覆盖全局选项。

这种机制支持动态加载的工具：在对话期间检索或加载的工具通过附加的 tool-declare 消息宣布，之后模型的可用工具集扩展而无需重建前面的上下文。

**通道**

助手消息的主体组织成通道，这一概念受 OpenAI 的 Harmony 响应格式 [85] 启发：think 承载推理轨迹，response 承载用户可见的答案，tools 承载工具调用（图 16b）。

两种生成模式纯粹通过生成前缀选择——思考模式使用 [open]think[sep]，指令模式使用 [open]response[sep]——而不是通过单独的模板。

Kimi K3 仅支持保留思考：在思考模式下，think 通道始终保留在历史中——即使其内容为空也保留——以便模型在各轮次之间观察一致的消息结构；在指令模式下，历史消息仅包含 response 和 tools 通道。

**工具调用**

在 tools 通道内，每个调用都带有 tool 和 index 属性；index 编号在消息内并行调用，每个 tool-result 消息重复相同的 tool/index 对并遵循其调用顺序，以便结果与调用明确关联。

参数是类型化的：字符串参数显示为原始文本，而其他 JSON 类型的值紧凑序列化。因此，像代码这样的自由格式文本是一等公民，而不是转义的 JSON 字符串。

纯 JSON 回退块涵盖参数无法分解为类型化参数块的输入；它仅出现在输入 token 中，从不出现在模型输出中，其损失在训练期间被掩码。

**推理努力和选项**

推理努力作为 thinking-effort 类型的全局选项消息暴露，插入在工具声明之后和输入消息之前。该消息不是修改生成前缀或暴露 token 预算，而是用自然语言陈述请求的级别，并充当生成约束指令。

架构保留四个级别（low、medium、high 和 max），其中 Kimi K3 支持一个子集。这种表示将努力接口与模板语法解耦，并且它直接与 §4.1.1 和 §4.1.2 中描述的努力条件训练对齐。

更广泛地说，这是所有选项消息的通用实现：tool_choice、response_format 和 thinking-effort 各自被转换为放置在上下文中的简短自然语言指令，而不是转换为专用的特殊语法。

因为预训练模型已经很好地遵循此类指令，所以可以在很少或没有额外训练的情况下引入新选项——这直接体现了上述低对齐税设计原则。

## 5 基础设施

### 5.1 训练基础设施

#### 5.1.1 KDA 系统协同设计

KDA 的高效实现需要算法和系统的深度协同设计。我们开发了融合内核，将 KDA 的多个操作合并为单一 GPU 内核，减少内存访问和内核启动开销。

KDA 上下文并行将长序列跨多个设备分割，使百万 token 训练在内存和计算上都可行。状态感知前缀缓存识别并复用常见的 KDA 递归状态，减少重复计算。

这些优化使 KDA 在设备内、跨设备和跨请求中都能高效运行，为百万 token 上下文训练和推理奠定了基础。

#### 5.1.2 MoonEP：完美平衡专家并行

对于 2.8 万亿参数混合专家模型的预训练，我们开发了 MoonEP（Moonshot Expert Parallelism），这是一种新的专家并行策略。

MoonEP 实现完美平衡的专家执行，具有静态计算形状和零拷贝通信。关键创新包括：

- **静态计算形状**：每个设备在每个训练步骤中执行相同数量的计算，无论路由如何变化
- **零拷贝通信**：专家激活直接在设备间传输，无需额外的缓冲区拷贝
- **完美负载平衡**：结合分位数平衡（§2.3.3），确保所有设备充分利用

MoonEP 证明了对于任何路由器输出，冗余专家数量的上界为 E/R（其中 E 是专家总数，R 是设备数），且该界是紧的（§ E）。

#### 5.1.3 内存高效训练

在有限内存内维持高利用率需要多项优化：

- **梯度检查点**：选择性地保存激活，在反向传播时重新计算
- **混合精度训练**：使用 BF16 进行前向和反向传播，FP32 用于优化器状态
- **多模态编码器优化**：MoonViT-V2 的特殊优化减少视觉编码器的内存占用

这些技术共同使 2.8 万亿参数模型能够在可用硬件上高效训练。

### 5.2 服务基础设施

Kimi K3 在生产侧面临独特挑战：混合 KDA–MLA 架构需要在百万级 token 上下文中联合管理两种根本不同的缓存。其新模块和高度稀疏的专家需要为每个模块量身定制的内核，而生产流量混合了单请求成本跨越三个数量级的请求。

以下设计从三个层面应对这些挑战：

**引擎层面**

KDA 感知的前缀缓存将固定大小的循环状态打包到与 MLA KV 缓存相同的分页池中，使长前缀可以跨请求复用。这对于共享长系统提示或上下文的多个请求特别有效。

**设备层面**

专用内核最小化每 token 延迟和内存流量：

- **KDA 解码内核**：优化的递归状态更新和查询
- **Block AttnRes 内核**：高效的跨层注意力计算
- **稀疏 latent 混合专家模型内核**：针对 LatentMoE 的快速路由和专家执行

**集群层面**

缓存感知的亲和性调度优先将具有相似前缀的请求路由到同一设备，最大化缓存命中率。基于预算的准入控制防止过载，确保服务质量。

### 5.3 强化学习基础设施

#### 5.3.1 协同定位系统

我们的协同定位系统将模型推理与环境执行放置在同一节点上，减少通信延迟并提高吞吐量。这对于长时程智能体任务特别重要，其中模型和环境之间有数千次交互。

#### 5.3.2 可恢复沙盒

百万 token 智能体强化学习需要长期保持模型和环境状态。我们的可恢复微虚拟机沙盒提供：

- **持久化展开**：跨训练迭代保持长轨迹的部分进度
- **外部 KV 缓存保留**：将大型 KV 缓存存储在外部内存中，避免重新计算
- **自适应节流**：根据系统负载动态调整采样速率
- **状态快照和恢复**：在故障时快速恢复，无需从头开始

这些机制使单个智能体轨迹可以跨越数小时甚至数天，累积数百万 token 的上下文，同时保持训练效率和鲁棒性。

## 6 评估

我们在广泛的基准测试上评估 Kimi K3，涵盖编码、智能体、知识、推理和视觉任务。

### 6.1 编码任务

Kimi K3 在多个编码基准测试上表现优异，特别是在长时程软件工程任务上：

- **SWE-Marathon**：Kimi K3 达到 42.0%，优于所有其他模型
- **Terminal-Bench 2.1**：88.3%，接近最佳性能
- **ProgramBench**：77.8%，略优于 GPT-5.6 Sol

这些结果表明 Kimi K3 在理解大型代码库、执行多步骤修改和验证解决方案方面具有强大能力。

### 6.2 智能体任务

在通用和视觉智能体任务上，Kimi K3 展示了强大的工具使用和长时程规划能力：

- **BrowseComp**：91.2%，所有模型中最高
- **JobBench**：54.3%，仅次于 Fable 5
- **AutomationBench**：30.8%，领先所有其他模型

这些任务需要复杂的多步骤规划、精确的工具调用和对环境反馈的适应，Kimi K3 的强化学习方法在这些方面表现出色。

### 6.3 知识和推理任务

Kimi K3 在知识密集型和推理任务上保持竞争力，尽管在某些任务上仍落后于最强的闭源模型。

### 6.4 视觉任务

原生多模态架构使 Kimi K3 在视觉任务上表现良好，特别是在需要视觉和代码理解的任务上。

### 6.5 整体性能

总体而言，Kimi K3 在我们的测试套件中始终优于其他开源和大多数闭源模型，仅在整体性能上落后于 Claude Fable 5 和 GPT-5.6 Sol。

作为一个完全开源的模型，Kimi K3 为研究社区提供了前所未有的机会，可以研究和改进前沿级别的智能系统。

## 7 结论

Kimi K3 代表了在两个扩展维度上的同步推进：预训练规模和测试时计算。通过将模型规模扩展到 2.8 万亿参数，同时在百万 token 上下文上扩展强化学习和智能体能力，我们展示了开源模型可以达到前沿级别的性能。

关键创新包括：

- **架构进步**：KDA、AttnRes 和 Stable LatentMoE 在序列长度、网络深度和模型宽度上扩展信息流动
- **高效训练**：2.5 倍的缩放效率提升使大规模训练更加经济
- **强化学习**：跨多个领域和努力级别的系统化 RL 产生了通用且高效的智能体
- **基础设施创新**：从训练到服务的端到端优化使这一规模的系统实际可行

我们发布完整的 Kimi K3 模型权重，希望它能加速前沿智能的研究、部署和民主化。
