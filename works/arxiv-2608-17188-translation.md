## 摘要

多智能体 AI 工作流的瓶颈不仅来自模型质量，还来自 token 成本、延迟和上下文窗口质量。现有研究描述了智能体编排模式、内存架构和模型层优化，但缺乏实践证据：如何在不损害输出质量的前提下，降低完整生产工作流的 token 使用量。

本文提出了一个面向实践者的多智能体 AI 系统 token 优化与上下文窗口管理框架。该框架源于一个生产环境的内部看板系统，该系统摄入会议、邮件和聊天内容，通过 LLM 提取结构化工作项，并在多个工作流间路由摘要。本文描述了六种优化模式：上下文分层（context stratification）、一次抓取/本地处理架构（fetch-once/process-locally architecture）、模式约束提示（schema-contracted prompts）、token 感知降级链（token-aware fallback chains）、语义缓存（semantic caching）和智能体间通信压缩（inter-agent communication compression）。在生产流水线中，这些模式将实测冷启动延迟（cold-load latency）从运营基线的约 3.5-10.5 分钟降至 61-116 秒（六次计时运行），历史 token 分析估算 token 减少了 60-70%。

本文还报告了一项受控的上下文组合研究：在 11 个模型配置上进行 2,420 次验证性试验，使用 661 条匿名化的工作场所通信项，并对相关性进行评分。核心结果是反直觉的。在固定提示词为 10 个项目的情况下，用同领域的低相关性项目替换部分高相关性项目，反而提高了模型对目标项的相关性评分一致性，相比仅提供高相关性项目的情况。我们将此称为"相关性对比上下文"（relevance-contrast context）。一个候选解释（本文未验证）是，低相关性样本帮助模型校准什么才算相关。在涵盖全部 11 个配置的配对分析中，50:50 信噪比条件下的相关性准确率比 100% 信号条件提高了 +0.077（朴素 95% 置信区间 [+0.056, +0.098]，Cohen's d = 0.49，Holm 校正 p < .001，n = 220）。这 220 个配置-区块单元并非独立；按九个模型家族汇总时效应量为 +0.084（95% 区间 [+0.064, +0.103]），我们将其报告为语料库内的描述性比较，而非总体推断。后续的 Fusion-of-N 研究发现，学习型的多样本合成未能击败提取项 ID 的机械集合并集，这提示了一个简单的面向召回的提取部署规则。

本文的贡献是在模型研究与生产智能体实践之间搭建了一个可测量的工程层：不是新的模型架构，而是一组可复现的模式和评估方法，使智能体工作流更快、更便宜、更可靠。

**关键词：** token 优化、上下文窗口管理、多智能体工作流、LLM 编排、上下文组合、提示工程、AI 成本优化

## 1. 引言

智能体化 AI 系统通常以成本和延迟为代价换取任务性能提升。一个协调器调用多个由 LLM 驱动的步骤，每个步骤接收上下文，每个输出成为后续步骤的上下文，降级或审查循环可能重复工作。这使得 token 使用量快速复合。从用户视角看似适度的工作流，内部可能消耗数万甚至数十万 token。

成本问题不仅是财务问题。庞大或排列不当的上下文窗口会因将有用证据埋没在无关材料中而降低质量。因此，开发者面临一个文献中尚未充分明确的实践问题：应该向模型发送什么内容、以何种形式、在工作流的哪个阶段？

本文在编排层（orchestration layer）解决这一问题。它不声称改进模型内部、发明智能体工作流分类法或替代现有内存架构。相反，它询问构建者如何使现有智能体工作流高效且可测量。

### 1.1 贡献

本文做出四项贡献。

   1. 定义了六种面向多步 LLM 工作流的 token 优化模式，每种模式都与生产实现以及观测到的成本、延迟或质量效应相关联。
   2. 将上下文窗口管理框定为一门工程学科：一组用于剪枝、压缩、路由和测量上下文的技能。
   3. 报告了一项在 11 个模型配置上进行的 2,420 次验证性试验的受控上下文组合实验，表明同领域低相关性上下文可以通过提供相关性对比，改善模型对目标项的相关性评分一致性。
   4. 报告了一项聚焦的 Fusion-of-N 后续研究，表明对于面向召回的提取任务，重复样本的集合并集是一个强大的机械基线，学习型融合在此设置中未能击败它。

本文不发明新的智能体编排模式、智能体内存架构或模型层提示缓存，其主张范围也相应界定。它不断言同领域噪声对所有任务都有帮助，也不认为学习型融合在一般情况下无用。其贡献是上述实践者层。该层是对真实多阶段工作流中 token 和延迟成本变化因素的端到端描述，以及对这些变化背后工程学科的可教授框架。

统一原则很简单：**发送更少的上下文，但发送具有更好结构和更好时机的上下文。** 系统节省 token 不是通过向模型隐藏信息，而是通过确保每次模型调用仅接收该步骤所需的信息。

### 2.2 作为工程技能的上下文窗口管理

优化模式指向一门更广泛的学科：上下文窗口管理。正如内存管理和状态管理在早期时代成为软件工程的首要关注点，上下文窗口管理正在成为 AI 工作流工程的核心。

核心技能包括：

   1. **上下文剪枝**：知道何时旧对话或任务状态已经变得有害。
   2. **信息密度**：用更少的 token 和更少的歧义传达意图。
   3. **内存卸载**：将稳定事实移入文件、数据库或结构化内存，而不是反复将它们放入提示中。
   4. **并行发现**：并发收集独立的上下文源以减少墙钟时间（wall-clock latency）。
   5. **上下文污染检测**：识别何时无关上下文正在改变模型行为。
   6. **上下文校准**：找到特定任务的上下文过少与过多之间的平衡。

第 4 节的实证研究细化了这一校准思想。对于提取任务，危险并不总是"噪声太多"。同领域低相关性项目可以帮助模型设定相关性阈值。

## 3. 测量设计

评估分为两部分：生产流水线分析和受控的上下文组合实验。

### 3.1 生产流水线分析

生产分析使用 2026 年 2 月的 25 次流水线运行记录。其中六次运行有测量的经过时间，其余运行是在部署完整遥测之前捕获的。由于 token 使用量从一开始就未被仪器化，历史 token 计数是使用字符计数近似值估算的，并随后针对 API 使用元数据进行验证。这是一个重要限制，论文将 token 减少视为估算值而非精确测量。

尽管如此，生产比较仍然有用，因为优化后的冷启动延迟是从记录运行中直接观测到的，为 61-116 秒。预优化基线 3.5-10.5 分钟是在部署完整遥测之前捕获的运营估算，缓存命中加载在运营中近乎即时，但未单独基准测试。

### 3.2 上下文组合实验

受控研究使用一名知识工作者在一个工作周内以参与者为中心的通信流中的 661 条匿名化通信项：15 个会议记录、627 个邮件线程和 19 个聊天线程。每个项目由作者按 0-3 相关性量表评分：3 标记影响当前工作的决策、行动项、阻碍或承诺；2 标记团队成员希望在周总结中看到的相关状态或上下文，但非行动关键；1 标记没有决策、行动或显著状态的切向提及；0 标记与活跃工程工作无关的项目（完整评分标准在附录 D 中）。评分 2 或 3 的项目被视为信号；评分 0 的项目被视为低相关性同领域上下文。评分 1 的项目从验证性实验中排除，以增强对比。

验证性实验包括在 11 个模型配置上进行的 2,420 次试验。每个模型配置在每个条件下运行 20 个试验区块。每个提示包含 10 个项目，配置通过改变信噪比或信号项目在提示中的位置来变化。

比例配置比较 100% 信号、80% 信号、50% 信号、30% 信号和 10% 信号（即 10 个项目中分别为 10、8、5、3 和 1 个信号项目）。六个位置配置将信噪比保持在 50:50，并将信号项目放置在开头、中间或结尾，或者按三种散布模式之一将它们分散在提示中。

主要指标是相关性准确率（RelAcc，Relevance Accuracy）：模型的 0-3 相关性评分与人类标注之间的一致性，完全匹配给予满分，分数相邻时给予部分分。写 h 和 m 分别表示一个项目的人类和模型 0-3 评分，T 表示目标（信号）项目集合：

无法解析的模型输出评分为 0。由于 RelAcc 是在信号项目上计算的，它测量的是对目标项目的相关性评分，而非完整提取精确率。事实类型召回率（fact-type recall）、精确率和 JSON 解析成功率作为次要指标进行跟踪。事实类型召回率是，对于每个目标项目，模型恢复的人类标注事实类型的比例，对近似等效类型给予部分分（例如，决策报告为行动）；报告值是该项目级评分的均值。

### 3.3 Fusion-of-N 后续研究

Fusion-of-N 后续研究询问，是否应该由另一个 LLM 合并重复提取样本，还是由更简单的机械规则合并。单个模型为每个窗口生成五个独立提取样本。研究比较了单个样本、best-of-N 判断、LLM 融合和提取项 ID 的集合并集。

这项研究比主要的上下文组合实验范围更窄。它使用一个生成器/判断器模型（DeepSeek-V3.2，以其默认设置运行）、一个语料库，以及一个自融合设置，其中生成器和融合器是同一模型。它在本文中的作用是实践性的而非普遍性的。它测试了一个常见的部署直觉："LLM 应该智能地合并多个样本"。

### 4.2 相关性对比上下文：低相关性同领域项目有帮助

核心实证发现是，对于目标项目的相关性评分，仅包含高相关性项目的上下文窗口并非最优。当提示包含演示"不重要"外观的同领域低相关性项目时，模型实现了更高的相关性评分一致性。这是一个仅针对目标的一致性结果，而非整体提取精确率的证明收益。

表中每个 RelAcc 和召回值是该条件下所有 11 个模型配置和 20 个试验区块的均值。相关性准确率从纯信号条件上升到一个宽广的平台。50:50 和 30:70 混合并列（0.661），10:90 混合仅略低（0.648），因此收益最好理解为跨越约 30-50% 信号（50-70% 同领域噪声），而非位于单一最优点，事实类型召回率随着信号份额下降而继续上升。

主要对比，50% 信号相对 100% 信号，RelAcc 提高 +0.077（95% 置信区间 [+0.056, +0.098]，Cohen's d = 0.49，Holm 校正 p < .001，n = 220 个模型配置 × 区块对）。所有 11 个模型配置都显示正向原始方向，尽管下文讨论的最大推理变体的效应可忽略不计。由于比例条件使用嵌套信号子集，我们还运行了匹配项敏感性分析，仅在 50:50 条件中存在的相同五个信号项目上对 100% 信号条件评分，效应保持为 +0.076（95% 置信区间 [+0.053, +0.099]，p < .001）。由于模型配置并非独立，我们还以模型家族为分析单元总结效应。11 个配置归约为九个模型家族。三个 Claude Opus 4.7 推理设置算作一个家族，而 GPT-4o、GPT-5.4 和 GPT-5.5 是独立家族（图 2 中显示的 GPT-5.5 的高推理和最大推理运行是事后添加的，位于这 11 个配置集之外）。所有配置还共享相同的 20 个试验区块。对九个家族效应求平均给出 +0.084（跨九个家族的 95% 区间 [+0.064, +0.103]），按试验区块聚类给出 [+0.032, +0.122]。两个区间都不包括零。由于只有九个家族，我们将其视为有界有限语料库的描述性效应，而非总体层面的推断。完整模型列表在附录 D 中。

作为额外的稳健性检查，我们将验证性比例比较作为单独的双臂重复运行——原始语料库对比校正语料库（移除一个精确重复项和一个超出范围项，并从受影响的聊天项中剥离导出元数据，如时间戳和标题行）——同时保持原始人类相关性标签固定。此重复涵盖 11 个模型配置中的 10 个（Llama-3.3-70B 在重运行时已退役），因此其原始语料库臂（+0.092）是新测量，而非冻结的 +0.077 标题值。增益在两臂上都保持明显为正——原始语料库 +0.092，校正语料库 +0.083——均在 +0.077 标题值的范围内。校正减去原始的小差异（−0.008）未能通过敏感性检查，不被解读为效应的真实减少（第 7 节和附录 D 给出完整的双臂结果）。

此结果不意味着任意无关上下文有帮助。低相关性项目是同领域工作场所通信，而非不相关的干扰项。可能的机制是阈值设定。当所有项目都相关时，模型没有普通低优先级内容的示例，倾向于高估相关性。由于主要的 RelAcc 指标聚焦于信号项，此机制是由相关性评分行为支持的假设，而非完整的精确率/F1 解释。

### 4.3 位置效应更小且依赖于模型

位置实验发现的效应小于比例实验。在所有 11 个模型配置中，将信号项目放置在 10 项提示的末尾，相比放置在开头，RelAcc 提高 +0.022（d = 0.14，未校正 p = .033），但该效应未能通过五个计划对比的 Holm 校正（p_adj = .098）。预期的"迷失在中间"效应在此规模下未被检测到。将信号项目分散在提示中也未击败连续放置（对比 C3，零假设）。中间放置与开头和结尾放置的平均值在统计上无法区分，对小的中间放置惩罚的检验力较低。

这不与先前的长上下文发现矛盾。此处的提示窗口按长上下文标准是短的：10 个项目，约 2,000-3,000 token。一个单独的 30 项窗口探索性条件表明，埋没效应在更大的提示大小时出现。因此实用规则是规模依赖的。对于短提取窗口，比例比位置更重要。对于更长的检索窗口，不要将最重要的内容埋在中间。

### 4.4 领域过滤是一个大的质量杠杆

探索性阶段发现，当源类型在信号密度上差异显著时，分别处理每种通信类型可能优于在一个提示中混合会议、邮件和聊天。在此数据集中，一项探索性（非验证性）分析发现，路由到仅会议内容使 RelAcc 提高了约 +0.16（0-100 量表上的 16 点），相比混合源提示。由于此比较是探索性的，它不属于预先指定的验证性实验，我们将其报告为指示性而非已确认。

原因是组合性而非语义性。在此数据集中，会议自然是高信号的，73.3% 的会议项目相关，而邮件项目仅 5.1%。因此，按内容类型路由在模型看到提示之前就改变了信号分布。这支持模式 1。上下文分层不仅是 token 节省技术，也是质量改进技术。

### 4.5 推理预算与校准效应（探索性）

研究包括对一个模型家族（Claude-Opus-4.7，在验证性集中）的完整推理预算扫描，以及之后添加的第二个家族（GPT-5.5）的匹配扫描。点估计朝相反方向移动。对于 Claude，校准上下文增益随推理预算上升而下降（默认 +0.078，高 +0.050，最大 +0.013），仿佛扩展推理让模型在内部推断相关性阈值，而不需要低相关性项目的示例。对于 GPT-5.5，增益随推理上升（默认 +0.048，高 +0.058，最大 +0.098）。

表面上看，这种镜像是引人注目的，但我们不将其视为真实效应。两个模型内趋势在统计上都无法与噪声区分（按试验区块配对，Claude p = 0.10，GPT-5.5 p = 0.15）。两个家族之间的符号差异——"相反方向"解读所依赖的交互作用——名义上显著（p ≈ 0.015，n = 20 个区块），但它仅基于两个模型家族，GPT-5.5 扫描是事后添加的，且测试未针对我们检查的几个推理对比进行校正——因此我们将相反方向模式报告为探索性假设，而非发现。确定推理预算是否调节校准效应需要一项专门的、具有足够检验力的跨多个模型家族的扫描。图 2 显示了每个配置，包括两次推理扫描，每个配置的数字在附录 D 中制表。

### 4.6 Fusion-of-N：集合并集是强基线

Fusion-of-N 后续研究发现，在此设置中，学习型 LLM 融合未能击败重复提取样本的机械并集。项 ID 的集合并集达到观测到的召回上限，融合器倾向于丢弃仅一个样本捕获的低支持真正例。

提示不变的结论不是"融合总是坏的"。面向召回的融合器提示改善了融合，并改变了与 best-of-N 的比较。稳健的结论更窄且更有用。对于面向召回的提取，如果多个样本识别项 ID，集合并集是一个简单、强大的基线，在此研究中学习型融合未能击败它，因此其额外计算在此处不合理。

## 5. 实践者指南

结果转化为五条部署规则。

   1. **不要过度过滤提取提示。** 如果任务是识别重要项目，请包含一些同领域低相关性项目，以便模型可以推断相关性阈值。在此语料库中，增益集中在低基础率源（邮件）中，对会议和聊天接近零，因此在依赖它之前按源类型测试。

   2. **当源类型在信号密度上不同时，在调用模型之前按内容类型路由。** 会议、邮件和聊天通常应分别提取，但增益取决于源桶具有不同的信噪比特征。

   3. **在升级模型之前优化上下文排列。** 排列更改测试成本低，在此研究中产生了可测量的质量变化，因此在承诺模型升级之前值得尝试。

   4. **将位置视为次要杠杆。** 在短上下文大小下，比例更重要。在更长的上下文大小下，避免将重要内容埋在中间，直到该假设针对你的任务进行测试。

   5. **将学习型融合与集合并集进行基准测试。** 如果重复提取样本可用，首先对项 ID 进行并集，仅在它击败目标指标上的机械基线时才添加融合器。

这些规则刻意是可操作的。目标不是产生提示的普遍定律，而是给构建者提供可在他们自己流水线中测试的具体默认值。

上述排列规则的参考实现——校准比例批处理、类型路由和位置排序——与本文一起作为 context_arranger.py 发布（MIT 许可证，仅 Python 标准库，无外部依赖）。它面向已经有检索或预过滤步骤并希望有一个即插即用的检索后排列层的实践者。传递带有来自你自己检索评分的可选相关性提示的项目，它将按上述规则对它们进行分组和排序。该工具仅实现排列指南。它不实现或验证相关性判断器。当没有预计算评分可用时，为方便起见包含了基于关键词的降级，但该启发式不是本研究中使用的方法（使用人类 0-3 相关性标签），也未经独立验证——在生产中依赖它之前，用你自己的检索评分或模型调用替换它。

该工具还支持显式位置参数——开头、结尾或交错散布模式——从本文技术附录（附录 D，"每模型位置敏感性"）中每模型分析得出的每模型位置偏好查找表、可配置的长上下文阈值以及可选的 token 预算感知批处理。请参阅技术附录以了解完整的每模型细分，以及工具自己的文档以了解完整的参数集及其警告。

## 6. 相关工作

Anthropic 的"构建有效的智能体"（Building Effective Agents）描述了常见的工作流模式，如链接、路由、并行化、编排器-工作器和评估器-优化器循环。本文通过测量这些工作流内部的成本和上下文效应来补充该分类法。

Lilian Weng 的"LLM 驱动的自主智能体"（LLM Powered Autonomous Agents）、Park 等人的"生成式智能体"（Generative Agents）和 Shinn 等人的"Reflexion"将内存和反馈框定为长期运行智能体行为的架构。本文聚焦于一个更窄的生产问题——当内存和上下文可用时，应该向每个模型调用发送多少？

Liu 等人的"迷失在中间"（Lost in the Middle）表明，长上下文模型经常未充分利用放置在长提示中间的信息。本研究发现，该效应在 10 项提取规模下不可见，但可能在更长窗口时出现，这表明存在规模依赖的边界。

Shi 等人关于干扰项的工作表明，无关内容会损害推理任务。Cuconasu 等人的"噪声的力量"（The Power of Noise）表明，随机文档有时可以改善 RAG 问答。本研究最接近第二类工作，但在任务和机制上有所不同。它研究同领域工作场所通信上的相关性评分和提取，而非检索段落上的答案生成。

提示压缩追求与此处研究的相反杠杆。它不是添加校准上下文，而是移除低信息 token，以便更多内容可以适应固定预算。Huiqiang Jiang 等人的 LLMLingua 丢弃小语言模型发现可预测的 token，使用预算控制器和迭代 token 级压缩在高压缩比下保留含义。LongLLMLingua 添加问题感知压缩和上下文重排序以对抗长输入中的位置偏差，LLMLingua-2（Pan 等人）将压缩重构为通过从更大模型蒸馏学习的 token 分类。这些方法在保持任务准确性大致固定的同时优化 token 成本。本研究是互补的，并指向一个边界条件。对于相关性评分和提取，一些同领域低相关性内容不是冗余的而是承重的，因为它提供了模型用于校准什么算作重要的对比。这表明在相关性敏感任务上存在压缩与校准的权衡——积极修剪"无聊但主题相关"的内容可以节省 token，同时悄悄削弱相关性校准——而表征该权衡从何处开始留待未来工作。

提供商提示缓存和缓存前缀在模型服务层减少重复提示前缀的成本。本文中的语义缓存模式在工作流层运作。当请求语义匹配先前计算的流水线结果时，它完全避免模型调用。

Li 等人的"更多智能体就是你所需要的"（More Agents Is All You Need）、自一致性（self-consistency）、智能体混合（Mixture-of-Agents）和 LLM-Blender 激发了采样和聚合。本文中的 Fusion-of-N 结果增加了一个部署警告。对于提取召回，机械集合并集可能难以被学习型融合击败。

相对于这些文献，本文的贡献是实践者工程层而非新架构或单一基准：一个端到端框架，用于减少多阶段智能体工作流中的 token 和延迟成本，一个可教授的上下文窗口管理框架，一项在 11 个模型配置（九个模型家族）和 2,420 次验证性试验上的受控上下文组合测量，表明同领域低相关性上下文可以改善提取校准，以及一个 Fusion-of-N 部署警告，表明在此面向召回的设置中，免费的集合并集是一个强基线，学习型融合未能击败它。

## 7. 局限性、伦理与发布控制

研究有重要局限性。

   1. 数据集是一名知识工作者在单周和单领域的以参与者为中心的通信流，发现可能无法推广到其他通信风格、工作者或设置。




                                                16

2. 所有人工相关性评分均由作者标注；这是有意采用的单标注者设计。由于标签在所有条件下保持不变（见第 8 条），报告的对比结果反映的是提示组合方式，而非标签共识。
3. 生产管道的历史 token 计数为估算值，因为完整的遥测系统是在初始优化工作之后添加的。
4. 主要的相关性指标是任务特定的、以信号项为中心的，不应直接与标准基准测试的准确率或精确率/召回率指标进行比较。
5. 比例配置使用嵌套的信号子集。上述匹配项敏感性分析降低了但并未消除对独立采样项集复现的需求。
6. 220 个配对测量并非独立——它们在 9 个模型家族和 20 个试验区块内聚类。考虑这种依赖性后，以模型家族为分析单位时效应为 +0.084（95% 置信区间 [+0.064, +0.103]），按试验区块聚类时为 [+0.032, +0.122]，两个区间均不包含零。由于只有 9 个家族，我们将其报告为有界的有限语料库描述性效应，不附加总体层面的 p 值，因为推广到更广泛的模型总体需要独立采样的聚类。
7. 加载器可见的语料库保留了同领域的遗留问题——29 行导出元数据混入聊天内容、至少一个无标题的聊天记录、一个完全重复的内容组——这些在试验中被重复使用，全部局限于聊天来源。对现有试验的留出敏感性分析表明这些遗留问题并未驱动该发现。排除受影响的聊天目标项后，校准上下文增益从 +0.077（所有来源）上升至 +0.112，仅限电子邮件目标项时上升至 +0.156，且效应在所有 11 个模型配置和所有 9 个模型家族中保持为正。由于效应集中在电子邮件项上，而遗留问题位于接近零效应的聊天来源中，这些遗留问题出现在效应最弱的位置而非驱动报告结果，校正语料库的重新运行（第 9 条）直接测试了这一点。这是对原始生成结果的排除分析，而非在重建语料库上的重新生成，后者仍是残留的局限性。
8. 由于所有相关性标签在两个实验分支中保持不变，+0.077 的效应反映的是提示组合的变化而非标注，因此单标注者主观性本身无法解释它。
9. 在校正语料库上的直接重新运行——删除一个完全重复项和一个超出范围的项，从受影响的聊天项中剥离导出元数据，保持原始标签不变——以约 +0.083 的增益复现了该效应，两个分支均明显为正。与原始语料库的微小负差异无法可靠解释。它在严格的对称留出少量无法解析的提示后无法保持，在重新归一化检查下缩小了约四分之三，甚至出现在运行间无法漂移的版本固定模型中，因此我们将其报告为描述性的，而非真实变化的证据。完整的两分支数据见附录 D。

**伦理**。语料库为作者本人的以参与者为中心的通信流。其他参与者编写的内容仅以匿名化的聚合形式出现。未发布原始消息、姓名或标识符，也未尝试重新识别任何个人。

**发布控制**。底层通信数据未公开。原始提示、原始模型输出、逐项 ID 和消息内容保持私有，公开论文和附录仅报告聚合统计、已命名模型和系统描述。

因此，本论文应被理解为一项具有对照实验支持的实践者系统研究，而非一个通用基准测试或关于所有人、所有模型或所有提取任务的主张。

## 8. 结论

多智能体工作流中的 token 优化是一个工程问题，而不仅仅是模型问题。通过改变上下文的获取、路由、压缩、缓存和测量方式，生产系统可以变得更便宜、更快、更可靠。

案例研究表明，编排层的变化可以将延迟降低数倍，并消除缓存路径上的重复 token 使用。对照实验增加了一个更令人惊讶的结果。对于提取任务，同领域的低相关性内容可以通过为模型提供对比来提高相关性准确率。Fusion-of-N 后续研究增加了最后一条部署教训。在添加另一个模型调用之前，应测试简单的机械基线，例如集合并集。

更广泛的主张是，上下文窗口管理应该成为一项一流的工程技能。随着上下文窗口的增长，问题不会是我们能否发送更多上下文。问题将是我们能否在正确的时间，以正确的结构，发送正确的上下文。

   1. **解析失败敏感性**。少量提示返回了无法解析的输出（原始语料库 5 个，校正语料库 8 个）。在两个语料库上对称地留出每个这样的位置，并通过非重新归一化评分规则重新计算，使增益——因此差异——在两个分支上都变为不可估计。负号在严格对称留出下无法保持。一个保持可用数量的更柔和的重新归一化检查将差异缩小了约四分之三，从 −0.00825 到 −0.00202。
   2. **漂移诊断**。两个分支收集时间间隔约十小时，因此版本服务模型原则上可能在它们之间漂移。将面板分为五个版本固定模型（可复现，无漂移）和五个按版本服务模型显示，差异即使在版本固定子集中也是负的（−0.00250），因此运行间的差距不是产生它的必要条件。按版本服务子集显示更大的负值（−0.01400）。这些是没有不确定性带的小型汇总诊断，因此它们将差异置于测量和漂移带内，而非解决其符号。

## 附录 E：Fusion-of-N 后续研究

**目的**：测试多个提取样本的学习型合成是否优于更简单的基线。

**设置**：DeepSeek-V3.2 为每个窗口生成五个独立的提取样本。然后同一模型充当评判者/融合者。任务是在噪声和窗口长度一起变化的生态稀释水平下进行面向召回率的提取。

同一模型既生成样本又充当融合者/评判者。这种自我偏好偏差如果存在的话会有利于模型自己的融合。简单的集合并集仍然胜过它这一事实使"并集获胜"的结果是保守的而非夸大的。

**结果**：学习型融合未能胜过提取项 ID 的免费集合并集。并集达到了召回率上限，而融合有时会丢弃仅由一个样本找到的真阳性。

此处的召回率是项识别召回率——恢复的目标项 ID 的比例——与主研究的事实类型召回率（第 3.2 节）不同。
