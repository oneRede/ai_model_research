# 大规模隐藏解码：大语言模型的潜在计算扩展

001

微信 AI 团队

###### 摘要

大语言模型（LLM）的扩展主要通过增大 Transformer 骨干驱动，但对于已经很强的模型，这需要另一轮昂贵的预训练。我们研究在保持 Transformer 骨干固定的情况下，通过为每个 token 分配更多计算来持续改进现有骨干的可能性。深度循环（looped）Transformer 追求这一目标，但难以扩展，因为循环计算与用于训练最大模型的流水线并行不自然兼容。我们沿着序列长度维度增加计算，额外的计算只是更长的输入，与标准的大模型训练保持兼容。我们提出 Hidden Decoding（隐藏解码），一种在持续预训练（CPT）期间应用的序列长度扩展方法。它将每个 token 扩展为 $n$ 个具有独立嵌入表的流（stream），并保留中间流的键值缓存作为上下文，因此每个 token 在不添加或加宽 Transformer 层的情况下执行更多内部计算。为了在规模上保持可负担性，我们引入流因子化注意力（Stream-Factorized Attention），其中大多数层仅在每个流内注意，只有少数层跨流混合，将注意力成本从 $n$ 的二次方降低到大致线性。实验支持两个扩展结果。在前沿规模上，我们在 $n=4$ 时训练 WeLM-HD4-80B 和 WeLM-HD4-617B，并改进其匹配的非 HD 基线，使 Hidden Decoding 成为首个在 100B+ MoE 规模上展示的序列长度扩展方法。在扩展因子上，随着 $n$ 增加，增益不断增长，表明序列长度扩展是前沿规模 LLM 的实用固定骨干扩展路径。

## 1 引言

扩展一直是大语言模型（LLM）进步的主要来源。增加模型大小、训练数据和训练计算一直持续产生更强的模型。然而，对于已经很强的基础模型，进一步扩展 Transformer 骨干的成本很高：通常需要另一轮大规模预训练，并增加训练和服务成本。这激发了本文的设定：通过在保持 Transformer 骨干固定的同时为每个 token 提供更多内部计算来改进现有骨干。

最近的推理模型和测试时扩展研究表明，即使参数固定，在每个问题上花费更多计算也可以提高准确性。这激发了最近潜在推理工作开始追求的目标：将部分额外的思考计算从可见 token 转移到模型的内部计算中。

朝着这一目标的一个突出方向是循环深度或循环式 Transformer，它通过在每个 token 上多次重用相同的 Transformer 块来增加计算。这是一种使用固定 Transformer 权重集增加每 token 计算的直接方法。然而，它难以扩展。训练最大的 MoE 模型依赖于流水线并行，它假设每个输入只通过模型的各个阶段一次。循环模型打破了这一假设，因为它在每次迭代中将相同的隐藏状态反馈回相同的阶段，这会停滞流水线并让 GPU 闲置。与此一致，循环模型一直保持较小规模：最大的是 40B 稠密 LoopCoder，在没有流水线并行的情况下训练，而其他循环语言模型仍保持在几十亿参数。因此，循环仍然缺乏一种实用的方法来扩展到非常大的模型，同时保持 GPU 的高效利用。

一个关键观察是，序列维度计算比深度重用更适合大规模训练。沿着序列维度，扩展只相当于输入更长的输入，这与用于大模型训练的标准优化自然兼容。通用范式是将每个输入 token 沿序列扩展为多个流，在单次前向传递中处理扩展序列，并仅对最终流应用下一个 token 损失，因此中间流在不添加新 Transformer 层或加宽现有层的情况下增加每 token 计算。一个实例是并行隐藏解码 Transformer（PHD），它重复每个 token，但为了保持推理便宜，使重复 token 的 KV 瞬态：中间流可以在当前 token 内提供帮助，但它们不会作为独立的 KV 上下文为后续 token 保留。因此，能力扩展设置需要在 CPT 期间跨位置保持可用的持久中间流状态。

在这项工作中，我们提出了一种名为 Hidden Decoding 的序列长度扩展方法，它通过持续预训练（CPT）改进前沿规模 LLM 的能力。两个设计选择使扩展流对能力扩展有用。为了给不同的流提供不同的初始状态，我们将词汇嵌入表复制为 $n$ 个每流表，将每个 token $x_i$ 扩展为流 $(E_1(x_i), E_2(x_i), \ldots, E_n(x_i))$；通过 CPT，这些表学习同一 token 的不同初始表示。为了让中间计算跨位置持久化，我们保留中间流的 KV，因此跨流累积的计算作为后续 token 的上下文保持可用。

保留所有流的 KV 使中间计算对后续 token 可用，但也使注意力成本增长为 $O(n^2L^2)$，这对于具有长序列的大模型来说训练不可行。因此，我们引入流因子化注意力。关键思想是将跨流注意力限制在层的子集：大多数层仅在每个流内注意，流仅在其余层交换信息，这些层遵循基础模型的注意力模式（滑动窗口，或当基础模型使用全注意力时为全注意力）。因为这样在大多数层避免了对完整 $nL$ 序列的密集注意力，所以增加的注意力成本保持大致线性而非 $n$ 的二次方。这种效率使 Hidden Decoding 能够在超过 100B 参数的 MoE 模型规模上进行训练，这是之前的循环或长度扩展方法未达到的范围。

实验直接测试两个扩展主张。为了测试 Hidden Decoding 是否扩展到 100B+ MoE 范围，我们在 $n=4$ 时训练 WeLM-HD4-80B 和 WeLM-HD4-617B。WeLM-HD4-80B 在所有九个共享基准上都优于 WeLM-80B，在 SciCode ($45.8 \to 50.0$) 和 PHYBench ($69.8 \to 73.8$) 上有较大提升。WeLM-HD4-617B 也在所有九个共享基准上优于 WeLM-617B，包括 GPQA Diamond ($89.1 \to 91.2$)、HLE ($33.6 \to 35.4$) 和 FrontierMath ($49.0 \to 51.0$)。这些结果使用早期仅 SFT 的后训练配方：每对匹配的非 HD 和 HD 模型使用相同的 SFT 训练配方，具有短的监督微调计划且没有强化学习。我们将它们用作受控比较；成熟的 WeLM 发布分数不在本文范围内。为了测试扩展因子本身是否提供扩展，我们在 80B 渐进扩展研究中将 $n$ 从 $2$ 增加到 $8$。MMLU 单调改进 ($85.0 \to 86.7 \to 87.5$)，Pile-test BPB 从 $0.386$ 降至 $0.378$。这些结果共同确立了序列长度扩展作为前沿规模 LLM 的实用固定骨干扩展路径。

**主要贡献**

1. **前沿规模固定骨干扩展。** 据我们所知，我们是第一个通过持续预训练（CPT）在 100B+ MoE 规模上展示序列长度扩展的。这产生了两个关键模型 WeLM-HD4-80B 和 WeLM-HD4-617B，处于之前深度循环（looped）或长度扩展方法未达到的范围。

2. **高效序列长度扩展。** 为了使扩展序列在前沿规模上可训练，我们引入流因子化注意力：大多数层仅在每个流内注意，而一小部分混合流。这使注意力成本在 $n$ 上接近线性；在 WeLM-HD4-80B 和 WeLM-HD4-617B 上，$4\times$ 扩展序列每批次仅花费 $5.1\times$ 和 $4.4\times$，远低于密集注意力 $16\times$ 基线。

3. **扩展因子扩展。** 我们表明增加扩展因子可以改进语言建模损失和下游准确性，验证 $n$ 作为固定 Transformer 骨干的实用扩展旋钮。

## 2 方法

Hidden Decoding 是一种序列长度扩展方法，它在不增大 Transformer 骨干的情况下增加每个 token 接收的计算。每个输入 token 在 Transformer 内部以 $n$ 个并行流表示，因此长度为 $L$ 的序列在单次前向传递中作为长度为 $nL$ 的序列处理，在其预测之前为每个 token 提供 $n$ 个内部计算步骤。图 2 对比了 Hidden Decoding 与深度循环（looped）计算：Hidden Decoding 将额外计算放置在序列维度上，而循环计算沿深度维度重用骨干。本节形式化多流扩展和训练目标（§2.1），引入流因子化注意力以在规模上保持扩展可负担性（§2.2），并描述如何从收敛检查点逐步增长扩展因子（§2.3）。

#### 设置和符号

标准 Transformer 语言模型通过单个词汇嵌入表 $E$ 映射每个 token $x_i$ 以形成输入序列 $(E(x_1), \ldots, E(x_L))$；它使用旋转位置编码（RoPE）添加位置，应用因果注意力，并通过共享头 $g_\theta(\cdot)$ 从每个位置的隐藏状态预测下一个 token。Hidden Decoding 保持此路径不变，仅改变每个 token 如何嵌入到序列中。

**图 2**：循环潜在计算 vs. Hidden Decoding。(a) 深度循环（looped）计算在预测下一个 token 之前对每个 token 的隐藏状态重用相同骨干 $f_\theta$ K 步。(b) Hidden Decoding 将每个 token 扩展为 n 个具有独立嵌入表 $E_1, \ldots, E_n$ 的流，将它们交错为长度为 nL 的序列，在单次通过相同骨干处理。下一个 token 交叉熵仅应用于最终流位置 ($E_n/h_n$)；早期流 ($E_1, \ldots, E_{n-1}$) 不接收损失并充当潜在计算状态。该面板显示两流示例。

### 2.1 多流 Token 扩展

Hidden Decoding 的核心构造是将标准模型的单个嵌入表替换为 $n$ 个独立嵌入表，我们称之为*流*，并将它们的输出交错到一个更长的输入序列中。

#### 扩展序列

给定输入序列 $X=(x_1, \ldots, x_L)$ 和 $n$ 个嵌入表 $E_1, \ldots, E_n$，我们通过将 token $x_i$ 的流 $k$ 表示放置在物理位置 $t=(i-1)n+k$ 来形成长度为 $nL$ 的扩展序列 $S$：

$$S_t = E_k(x_i), \quad 1 \leq i \leq L, \quad 1 \leq k \leq n.$$

对于 $n=2$，这产生 $S=(E_1(x_1), E_2(x_1), E_1(x_2), E_2(x_2), \ldots)$。扩展序列在标准因果注意力下输入相同的 Transformer，具有连续的 RoPE 位置 $0, 1, \ldots, nL-1$。扩展因子 $n$ 直接控制添加多少额外的每 token 计算。

#### 训练目标

仅监督每个 token 的最终流 $E_n(x_i)$：从其隐藏状态我们通过共享语言建模头 $g_\theta$ 预测下一个 token $x_{i+1}$，而前 $n-1$ 个流不接收直接损失。令 $h_t$ 表示物理位置 $t$ 的隐藏状态，目标是仅在最终流位置 $t=in$ 应用的下一个 token 交叉熵：

$$\mathcal{L}(\theta) = -\sum_{i=1}^L \log g_\theta(x_{i+1} \mid h_{in}).$$

因为注意力是因果的，最终流 $E_n(x_i)$ 注意同一 token 和所有先前 token 的所有早期流。因此，前 $n-1$ 个流充当中间计算状态，在最终承载预测的流之前逐步细化表示。仅监督最终流并给每个流自己的嵌入表赋予中间流这种潜在计算角色；监督所有流或在预测前求和它们的输出会降低 §5.1 中监督设计消融的性能。

### 2.2 流因子化注意力

在 $nL$ 个扩展位置上运行密集注意力的成本为 $O(n^2L^2)$，因此对于具有长序列的大型 LLM，训练成本急剧增长。流因子化注意力通过使大多数层仅在流*内*注意并将跨流混合限制在层的子集来减少这一点。

#### 流和 token 索引

对于扩展序列中的位置 $t \in \{1, \ldots, nL\}$，令其 token 和流索引为

$$i(t) = \lceil t/n \rceil, \quad s(t) = ((t-1) \bmod n) + 1,$$

使得 $S_t = E_{s(t)}(x_{i(t)})$。连续的 $n$ 个位置块对应连续的 token，$n$ 个流在每个块内排序。

#### 流内和跨流层

使用公式 3 中的索引，*流内*层将注意力限制在同一流的早期位置，

$$M^\text{intra}_{t,t'} = \mathbf{1}[t' \leq t \wedge s(t') = s(t)],$$

其成本为 $O(nL^2)$ 而不是密集层的 $O(n^2L^2)$；*跨流*层也跨流注意，遵循模型通常的注意力模式。图 3 说明了三种结果掩码类型。

#### 设计

大多数层是流内的，跨流注意力仅在层的子集启用。我们不为此添加新的注意力层：我们重用基础模型自己的注意力层作为跨流层。当基础模型包含滑动窗口注意力时，这些层充当跨流层，因此跨流注意力是局部的；否则跨流层是全注意力层。因为大多数层是流内的，增加的注意力成本保持接近 $n$ 的线性而非二次方（§3）；跨流层的数量和放置是我们在 §4 中研究的设计选择。这种布局还使 CPT 更接近 HD 扩展前的检查点：大多数层保留基础模型的单流因果路径，而只有少数层引入跨流扰动；附录 H 给出了此效应的单独 617B 规模启动损失检查。

### 2.3 渐进式扩展

可以直接训练大扩展因子 $n$，但逐步增长它为许多嵌入流提供更好的初始化并节省计算。因此，我们逐步增长因子——$1 \to 2 \to 4 \to 8$——从前一个的收敛检查点初始化每个因子。具体来说，我们使用*循环复制初始化*：当从 $n$ 加倍到 $2n$ 时，新流复制现有表，

$$E_{n+k} \leftarrow E_k, \quad 1 \leq k \leq n,$$

因此扩展模型最初重现较小模型的行为，然后平滑适应。例如，$n=2 \to 4$ 将表初始化为 $(E_1, E_2, E_1, E_2)$，$n=4 \to 8$ 为 $(E_1, E_2, E_3, E_4, E_1, E_2, E_3, E_4)$。在实践中，我们在持续预训练期间在计划的 token 计数时引入连续扩展，让每个因子在下一个扩展之前收敛。

## 3 计算成本

Hidden Decoding 为每个 token 添加计算，因此必须测量其训练和服务成本。我们区分两种成本：方法固有的成本（在任何骨干上都成立）和特定于我们 WeLM 骨干的额外节省。我们在 §4.2 中报告训练测量，在 §4.5 中报告服务测量。

### 3.1 训练成本

将每个 token 扩展为 $n$ 个流将长度为 $L$ 的序列转换为长度 $nL$。非注意力计算大致与位置数量成比例，但扩展序列上的密集注意力将扩展为 $O(n^2L^2)$，或未扩展序列注意力成本的 $n^2\times$。流因子化注意力（§2.2）通过保持大多数层流内来避免这种密集注意力爆炸，因此注意力成本保持接近 $n$ 的线性。这种接近线性的注意力设计是该方法固有的，在任何骨干上都成立。

我们的 WeLM 骨干通过其 *KV 镜像*设计允许进一步的架构特定节省。在标准层中，键和值来自该层自己的输入隐藏状态；在 KV 镜像下，每个后层改为使用自己的投影权重从早期层的隐藏状态计算它们。层以 U 形配对，最后三分之一镜像前三分之一。因为镜像层的键和值仅依赖于早期层的隐藏状态，我们的训练框架在早期层计算它们，镜像层直接重用它们。

KV 镜像让 Hidden Decoding 跳过镜像层中的工作。仅监督最终流（§2.1），因此中间流仅通过它们作为上下文添加的键和值重要。在镜像层中，此上下文已由早期层固定，中间流不携带损失，因此这些层根本不需要处理中间流。因此，我们仅通过镜像层运行最终流，而早期层仍处理所有 $n$ 个流。在我们的 80B 和 617B 模型中，最后三分之一的层是镜像的，因此中间流在最后三分之一中被跳过。此节省特定于 WeLM；它在流因子化注意力已在任何骨干上提供的接近线性成本之上。作为实现检查，此 KV 镜像优化在 80B 32k 训练设置中将每批次时间从 $15\,\mathrm{s}$ 减少到 $12\,\mathrm{s}$，减少 $20\%$（$1.25\times$ 加速）。我们使用此数字量化 WeLM-HD4-80B 和 WeLM-HD4-617B 使用的 WeLM 特定训练系统节省；§4.2 中的主要成本比较报告长上下文设置下的端到端 HD 训练时间。净效应是训练成本随流数 $n$ 接近线性增长。我们在 §4.2（图 4a）中在两个规模上测量这一点。

### 3.2 推理成本

Hidden Decoding 相对于循环模型的一个关键优势是其额外计算并行运行。循环模型通过逐步重复骨干来添加计算，每一步等待前一步，因此无法隐藏添加的成本。Hidden Decoding 将其计算分散在 $n$ 个流上，它们在单次前向传递中一起处理。在大批量大小时，解码受计算限制，因此这种额外计算降低吞吐量。在小批量大小时，解码受内存带宽限制并使大部分计算闲置；并行流可以使用该闲置计算，因此添加的成本保持较小。此范围内唯一剩余的开销是更大的 KV 缓存，流因子化注意力通过仅在少数层读取完整扩展 KV 来保持适度。因此，吞吐量惩罚在延迟敏感、短输入/小批量范围内最小，并随着更大批量或更长输入而增长，正如我们在 §4.5 中测量的那样。

对于 WeLM 模型，KV 镜像也可以通过跳过中间流的镜像层工作来减少解码端计算。§4.5 中的服务基准使用当前基准实现，没有此额外的 KV 镜像解码优化，因为将其集成到解码内核需要单独的工程。因此，报告的吞吐量不包括此 WeLM 特定加速。

## 4 实验

我们在多个规模上测试 Hidden Decoding：在前沿 MoE 规模上的受控匹配比较（§4.1, §4.2），一个稠密模型上的扩展因子研究（§4.3），消融实验以理解设计选择（§4.4），以及吞吐量测量以量化服务成本（§4.5）。附录 E 给出了更多基准和扩展行为的额外表格；附录 I 给出了预训练阶段的损失和评估曲线。

### 4.1 训练设置

#### 骨干模型

我们的两个主要前沿规模 MoE 检查点是 **WeLM-80B**（80B 总参数，3B 激活）和 **WeLM-617B**（617B 总参数，23B 激活）。这些是 WeLM 系列的内部检查点，其更大的 1T 形式已在 Kimi K2 技术报告中描述。两者都使用具有 KV 镜像的标准 MoE 架构，在滑动窗口（局部）注意力层和全注意力层之间交替。每个模型存在两种形式：基线（无 Hidden Decoding）和在持续预训练期间添加 Hidden Decoding 的 HD4 变体。两种形式的参数总数相同；扩展不会增加 Transformer 权重，仅改变每个 token 如何嵌入。

#### 后训练范围

用于早期后训练表格的后训练有意保持轻量级：这是一个早期的监督微调运行，不包括强化学习。我们使用此阶段测试 Hidden Decoding 的增益是否在非 HD 和 HD 模型的相同下游适应配方下持续存在。附录 D 给出了 SFT 配方。我们将这些分数报告为受控的早期 SFT 比较，成熟的 WeLM 发布分数留在本文范围之外。

#### 评估

我们使用两个评估套件。对于早期后训练结果（表 2 和 11），我们在涵盖数学和科学的最新困难基准上评估（HMMT 和 MathArena Apex、IMO-AnswerBench、FrontierMath、PolyMath、GPQA、PHYBench、CritPt），知识和推理（HLE、MMMLU、AA-OmniScience、AA-LCR、ARC-AGI-2），代码（SciCode、LiveCodeBench），指令遵循（IFBench）和智能体任务（Terminal-Bench 2、$\tau^{2}$-Bench、GDPval）。

对于扩展和消融研究（§4.3, §4.4）和预训练阶段结果（附录 I），我们使用标准套件：MMLU、MMLU-Pro、CMMLU、C-Eval、SuperGPQA、ARC-C、HellaSwag、BBH、GSM8K、MATH、SimpleQA、Chinese SimpleQA、HumanEval+/MBPP+、MultiPL-E 和 CRUXEval。表 8 和 9 给出了每个基准的设置。

### 4.4 注意力组成消融

为了测试准确性需要多少完全跨流混合，我们消融流因子化注意力内部的注意力组成。每一层以三种方式之一混合流：*全注意力*（跨所有流在整个序列上）、*局部*（在滑动窗口内跨流）或*流内*（无跨流混合）。全混合是昂贵的情况。

我们在 21B MoE 上运行此消融，它有 27 层，其基础模型已经交错全注意力和滑动窗口层。参考是标准的无扩展基线。三个 Hidden Decoding 变体仅在有多少层使用完全跨流混合上不同：1、4 或全部 27 层，其余层在局部和流内混合之间分配（确切布局在附录 F 中）。表 4 报告了评估的基准及其平均值。

每个 Hidden Decoding 模型在平均值上都击败无扩展基线，增益从 +1.55 到 +2.62。全全注意力模型最好，但更便宜的 4 层全注意力变体接近（+2.16），1 层全注意力变体仍然改进基线（+1.55）。少数全注意力层就足够了：其余的跨流混合可以是局部的或跳过的，这使流因子化注意力保持便宜，同时保留大部分准确性增益。

### 4.5 推理吞吐量

## 5 中间流的消融和探测

Hidden Decoding 依赖于一个不寻常的选择：只有最终流被训练来预测下一个 token，而早期流不接收直接损失（§2.1）。§4.2 中的匹配结果表明 Hidden Decoding 提高了准确性。仅准确性增益留下早期流扮演什么角色的问题：相对于无扩展基线的增益可能来自更简单的效应，如更长的扩展序列、更多预测目标或流输出的显式聚合。为了测试这些可能性，我们使用消融和探测。训练目标消融将最终流监督与全 token 损失和输出求和进行比较（§5.1）。KV 保留分析测试每流 KV 是否有用，流探测检查隐藏状态分离和最终流注意力（§5.2）。LM 头探测提供中间流状态的词汇空间视图（§5.3）。

### 5.1 训练目标消融

为了将最终流监督的效果与更简单的替代方案分离，我们在相同的 6B MoE 骨干和训练设置上训练目标变体。比较问询增益是否来自让中间流没有直接损失，或者当每个流接收预测目标或流输出被显式聚合时是否出现类似增益。基线没有流扩展。扩展变体包括*全 token 损失*，对每个流应用下一个 token 损失；*求和*，在预测前将流输出相加；以及 Hidden Decoding，仅监督最终流。主要比较对所有扩展变体使用相同的扩展因子 $n=2$；我们还报告 $n=3$ 时的 HD，以显示首选目标是否随着更多流继续改进。

表 5 报告了结果。在语言建模上，所有扩展变体都改进了无扩展基线，但 HD 在相同扩展因子下给出最低损失：$n=2$ 时为 1.874，而全 token 损失为 1.880，求和为 1.877。下游结果遵循相同的模式。$n=2$ 时的 HD 在所有四个报告的基准上最好，在 ARC-C 上分离最清楚（74.3 vs. 求和的 71.9 和全 token 损失的 65.8）。将 HD 增加到 $n=3$ 进一步将损失降低到 1.857 并改进所有四个分数。这些结果支持最终流监督优于对中间流的额外直接监督和流输出的显式求和。

### 5.2 KV 保留消融和流探测

Hidden Decoding 通常为每个流保留单独的 KV 缓存，因此后续位置可以使用早期中间流产生的计算。为了测试这种保留的每流 KV 是否有用，我们比较保持相同骨干、训练设置、扩展因子和流因子化注意力布局的两个 Hidden Decoding 变体。参考设置是正常的*每流 KV* 设计。受控变体是*共享 KV*，一个类似 PHD 的对照：它保持最终流预测目标和单独的流轨迹，但通过在流内层中使用跨流共享的一个 KV 缓存来移除独立保留的流 KV。如果中间流 KV 是冗余的，用这种类似 PHD 的对照替换每流 KV 应该几乎没有系统性影响。


我们在相同的 21B MoE 上训练此消融，使用 $n=2$ 并在两个配置之间共享流因子化注意力布局（附录 F）。表 14 报告了 Pile-test 损失和四个基准。共享 KV 在所有指标上都更差：损失更高（$1.989$ vs. $1.960$），所有下游分数更低，ARC-C 上的差距最大（$61.3$ vs. $69.4$）。这表明保留的每流 KV 不是冗余的；它对准确性有贡献。

| 每流 KV | 1.960 | 58.7 | 69.4 | 65.5 | 63.8 |
| 共享 KV | 1.989 | 57.2 | 61.3 | 63.4 | 62.1 |

为了更直接地检查流分离，我们对同一 21B 运行的每流 KV 和共享 KV 检查点进行流探测。对于每个流 $k \in \{1, \ldots, n\}$ 和层深度 $d$，我们在该深度从流 $k$ 的位置收集隐藏状态并训练一个 logistic 回归分类器来预测该隐藏状态来自哪个流。如果流携带不同的表示，分类应该比随机机会更好；如果它们完全纠缠，流预测应该保持在机会水平。图 6(a) 绘制了两个配置的所有 27 层的流预测准确率。每流 KV 配置在所有层都达到完美分离（准确率 = 1.0），而共享 KV 配置在大多数层保持接近 0.5 的机会水平，仅在几个早期流内层短暂上升到 0.8。这种对比确认每流 KV 让流保持不同的表示；共享 KV 使它们纠缠。

为了检查最终流是否使用早期流，我们计算每个查询位置（流 $q$，token $i_q$）对流 $k$ 内所有 token 的注意力质量，并在共享数据集上对每一层求平均。图 6(b) 绘制了结果：最终流 $s=2$ 在大多数层对流 1（$k=1$）给予 0.3–0.4 的注意力，而流 1 对流 2 给予接近零的注意力。这种不对称模式确认最终流依赖早期流；早期流不能看到后面的流（因为它们在序列中位置更早）。

![参见标题](imgs/img-006-stream-probes.png)

**图 6**：流探测（21B，$n=2$）。(a) 流分类准确率：每流 KV 在所有层都达到完美分离，而共享 KV 纠缠流。(b) 每流注意力质量：最终流（$s=2$）对早期流（$k=1$）给予约 0.3–0.4 的注意力，而早期流对最终流几乎没有注意力。

### 5.3 语言建模头探测

为了测试中间流如何改变模型对词汇空间的视图，我们在 21B 每流 KV 模型的所有层对流 1 和流 2 的隐藏状态应用冻结的语言建模头 $g_\theta(\cdot)$，然后检查流之间 top-k 预测的重叠。如果两个流产生相似的预测，它们的 top-k 集合应该高度重叠；如果它们考虑不同的假设，重叠应该更低。图 7(a) 为 $k \in \{1, 5, 10, 50\}$ 绘制每一层两个流之间的 top-k 重叠。

在早期层，流 1 和流 2 在所有 $k$ 值上都有高重叠（top-1 约 0.9，top-50 接近 1.0）。在后期层，重叠下降：top-1 重叠降至约 0.6，top-50 降至 0.9。这种差异表明，到最终层时，两个流通常对最可能的下一个 token 有不同的看法，即使它们的前 50 个列表仍然部分对齐。两个流之间的这种分歧与流探测一致（§5.2），流探测表明流携带不同的表示。图 7(b) 单独绘制流 2（最终流）相对于流 1（早期流）的熵。流 2 的熵在后期层低于流 1，表明最终流对其预测更有信心。

## 6 相关工作

**深度循环（looped）Transformers** 通过逐步重复骨干来增加每 token 计算。循环 Transformer、Universal Transformers 和相关工作证明了能力改进，但它们难以扩展到最大模型，因为循环计算不适合流水线并行，流水线并行假设每个输入只通过模型的各个阶段一次。已发布的最大循环语言模型仍保持在几十亿参数；本文首次在 100B+ 规模展示固定骨干扩展，使用与流水线并行兼容的序列长度方法。

**序列长度扩展** 是一种替代路线，将额外计算放置在序列维度上。PHD 通过在输入中重复每个 token 来追求这一点，但它不保留中间流的 KV，因此中间流不作为后续 token 的显式上下文持续存在。我们表明保留每流 KV 对能力有贡献（§5.2）。并行解码工作使用 draft 模型或自回归多 draft 来加速推理，而不是用于能力训练。Hidden Decoding 专注于能力扩展通过持续预训练，并优先考虑训练和推理在前沿规模上的可行性。

**测试时计算** 和最近的潜在推理工作探索给予推理时间更多计算。我们的持续预训练设置直接增加训练期间的每 token 计算，因此每个 token 学习在相同的流预算内更有效地思考。

**并行扩展** 与 MoE 平行：两者都将额外参数放置在并行路径上。MoE 增加模型宽度但保持每 token 激活参数固定；Hidden Decoding 增加每 token 序列但保持模型宽度和激活参数固定。两种范式都比增大稠密 Transformer 便宜，但扩展不同的维度。

**思维链**（CoT）和推理时扩展表明给予 token 预算可以改进准确性。Hidden Decoding 学习在持续预训练期间使用内部流；我们的探测（§5）表明流携带可区分的表示，最终流对早期流给予注意力，并且流在后期层对下一个 token 预测产生分歧。这种训练时每 token 计算的增加与推理时 CoT 正交。

**提示压缩** 和上下文长度扩展关注更长的输入。Hidden Decoding 增加每 token 内部计算而不扩展输入上下文。

## 7 限制与未来工作

Hidden Decoding 展示了序列长度扩展在前沿 MoE 规模上的可行性，但仍有改进空间。每流 KV 在小批量、短输入解码中的成本适中（§4.5），但在长输入、大批量设置中变得显著。仅在少数层使用全跨流注意力是一个有意的权衡：它使训练在大模型规模上可行，但牺牲了完全密集混合可能提供的一些准确性（§4.4）。未来的工作可以探索混合稀疏或内存高效的注意力变体，以在保持成本接近线性的同时实现更密集的跨流混合。

我们的渐进式扩展协议在每个因子之间引入明确的训练阶段。探索更平滑的扩展计划或在线扩展可能会导致更好的收敛。流因子化注意力布局在层级别是固定的；自适应混合可以根据每个 token 的需求动态路由跨流注意力。

Hidden Decoding 保持 Transformer 骨干固定。将其与传统的参数扩展或 MoE 增长结合可能会产生互补的增益。我们的消融表明保留的每流 KV 对准确性有贡献（§5.2），并且仅监督最终流优于对每个流应用损失（§5.1）。这些设计选择可以在不同的规模和设置下进一步优化。

本工作测量了两个规模（80B 和 617B MoE）和一个扩展因子轨迹（稠密 8B 模型从 $n=1$ 到 $8$）。探索更多规模、更多因子和不同的骨干架构将有助于理解 Hidden Decoding 何时提供最大价值以及成本-收益权衡如何变化。

## 8 结论

我们提出了 Hidden Decoding，一种通过持续预训练在前沿规模 LLM 上增加每 token 计算而不增大 Transformer 骨干的序列长度扩展方法。通过将每个 token 扩展为 $n$ 个具有独立嵌入表的流并保留它们的 KV 缓存，Hidden Decoding 让每个 token 在预测之前执行更多内部计算。流因子化注意力使此扩展在规模上保持可训练：大多数层仅在流内注意，将注意力成本保持接近 $n$ 的线性而非二次方。

在前沿规模上，WeLM-HD4-80B 和 WeLM-HD4-617B 在所有测试的基准上都改进了它们匹配的非 HD 对应物，在困难的数学、科学和智能体任务上有最大的增益。扩展因子研究确认增加 $n$ 稳步改进损失和准确性。训练成本保持接近线性（$4\times$ 扩展序列花费 $5.1\times$ 和 $4.4\times$），推理吞吐量在小批量、短输入解码中保持在基线的 83-88%。消融验证保留的每流 KV 是有用的，流探测确认流携带不同的表示，最终流对早期流给予注意力。

这些结果共同确立了序列长度扩展作为前沿规模 LLM 的实用固定骨干扩展路径，使 Hidden Decoding 成为首个在 100B+ MoE 规模上展示的序列长度扩展方法——这是循环模型难以应用的范围。
